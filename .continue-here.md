## The Bug: strategy_service._run_strategist_loop

### Root Cause
`strategy_service.py` uses `ClaudeSDKClient` (Claude Agent SDK) to run the strategist. The plan assumed the SDK would return `ToolUseBlock` for custom JSON tool schemas defined in the prompt. **This is wrong.** The Claude Agent SDK is a code-execution agent (it runs Claude Code CLI); it doesn't accept custom JSON tool schemas and never emits `generate_strategy` ToolUseBlocks.

### Evidence
```
# Debug run output:
Signals: {"chunk_count": 23, ..., "avg_chunk_len": 944.0, ...}
Result container: {}   ← EMPTY — no ToolUseBlock was captured
```

### Fix Required
Replace `_run_strategist_loop` in `apps/api/app/services/strategy_service.py` to use the **direct Anthropic API** (same pattern as `_expand_query` in retrieval_service.py):

```python
async def _run_strategist_loop(signals_json: str, result_container: dict) -> None:
    import anthropic
    client = anthropic.Anthropic()
    response = client.messages.create(
        model=SONNET_MODEL,
        max_tokens=500,
        system=_STRATEGIST_SYSTEM_PROMPT,
        tools=[_TOOL_GENERATE_STRATEGY],
        messages=[{
            "role": "user",
            "content": f"Corpus signals:\n\n{signals_json}\n\nCall generate_strategy."
        }]
    )
    for block in response.content:
        if block.type == "tool_use" and block.name == "generate_strategy":
            result_container["strategy"] = block.input
            return
```

NOTE: The `run_strategist` sync bridge (`asyncio.run(asyncio.wait_for(...))`) can stay OR be simplified since the direct API is synchronous. Simpler option:
```python
def run_strategist(signals_json: str, result_container: dict) -> None:
    import anthropic
    try:
        client = anthropic.Anthropic()
        response = client.messages.create(
            model=SONNET_MODEL,
            max_tokens=500,
            system=_STRATEGIST_SYSTEM_PROMPT,
            tools=[_TOOL_GENERATE_STRATEGY],
            messages=[{"role": "user", "content": f"Corpus signals:\n\n{signals_json}\n\nCall generate_strategy."}]
        )
        for block in response.content:
            if block.type == "tool_use" and block.name == "generate_strategy":
                result_container["strategy"] = block.input
                return
    except Exception as exc:
        log.warning("run_strategist.failed", error=str(exc))
```

If you simplify to synchronous, also update `synthesize_retrieval_strategy` in `strategy.py`:
- Replace `asyncio.run(asyncio.wait_for(_run_strategist_loop(...), timeout=60.0))` with just `run_strategist(signals_json, result_container)`
- Update the 4 task-layer tests in `test_strategy_task.py` — they patch `asyncio.run`; they'll need to patch `run_strategist` directly instead

### Unit Tests Implication
The current 9 tests pass because they mock `asyncio.run` at the module boundary. After the fix:
- `test_run_strategist_calls_asyncio_run` will need to be renamed/updated to test the actual mechanism
