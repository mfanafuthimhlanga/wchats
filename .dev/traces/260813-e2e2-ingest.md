# TRACE — E2E-2 · ingest (2026-08-13). GREEN, and it found a production-blocking defect

**Result: 8/8 assertions.** The ingestion chain has now run end to end for the first time.
**It did not work on the first attempt, and the reason is the most consequential finding of the day.**

## What it took

Three things had to change, in this order:

1. **The `pipeline` extra installed** — `docling==2.93.0`, `transformers 5.13.1`, `torch 2.13.0+cpu`.
   Never installed in repo history (`4.4`).
2. **An `S3_ENDPOINT_URL` seam + MinIO** (owner decision on `1.24`) — `c5c40b2`. The seam is refused
   outright when `ENVIRONMENT=production`; that rule is the justification for the seam existing.
3. **`1.26` fixed** — the defect below.

## `1.26` — ingestion has been broken for every uploaded file since PROD-13

First run of the fixed-storage chain:

```
parse_documents  succeeded
chunk_documents.error  document_id=13fa9b5e-...  error_type=FileNotFoundError
Retry in 4s: Retry(Retry(...), FileNotFoundError(2, 'No such file or directory'), 4)
```

PROD-13 moved document bytes to S3 and migrated `parse_documents`. **It did not migrate
`chunk_documents`**, which kept `_resolve_local_path()` — docstring *"Mirror of parse_documents
path-resolution"* — returning `UPLOADS_DIR/{agent_id}/{doc_id}{ext}`. It was an accurate mirror until
the thing it mirrored moved.

- **Nothing in `app/` writes a file to disk at all**: zero `write_bytes`, zero `open(..., "wb")`,
  zero `shutil.copy`. `chunk.py:85` was the last live consumer of `UPLOADS_DIR`, which `config.py:164`
  already described as off the hot path.
- **Scope: every file source type** (`pdf, png, jpg, jpeg, md`). Only URL sources, which re-fetch over
  HTTP in the `else` branch, could complete.
- **Not a local artefact.** On Fargate `/vrd-uploads` is an empty container path.

**Why nothing caught it — retro Family I, recurrence 7, and the sharpest instance yet.**
`test_ingestion_chain.py:347` writes its fixture to `gettempdir()/vrd-uploads/{agent_id}/{doc_id}{ext}`.
It does not mock the storage boundary; it **manufactures the local file production stopped creating**.
Those four tests have never run (`4.4`), and **had they run they would have passed** over a product
that could not ingest a single PDF. Family I has been "the code was correct; the shape it was handed
was never checked". Here the code was *wrong* and the fixture was maintaining the illusion that it
was right.

`_resolve_local_path` was **deleted**, not left unused — a dead helper naming a plausible contract is
how the next reader re-adopts it. The pin is `tests/unit/test_ingestion_reads_from_s3.py`: an AST scan
asserting **no** pipeline module references `settings.UPLOADS_DIR`. The class, not the instance —
`1.14`'s lesson.

## `1.27` — found only because the fix forced a three-way comparison

The S3 key's extension is derived in three places and they disagreed:

```
documents.py:191  Path(f.filename).suffix.lower()     <- the WRITER, the authority
parse.py:263      Path(source_uri).suffix              <- no .lower()
chunk.py:84       Path(source_uri).suffix or ".bin"    <- deleted with the helper
```

`Policy.PDF` is written to `{doc_id}.pdf` and read back as `{doc_id}.PDF` → `NoSuchKey`. **Latent, not
observed**: no fixture in the repo has an uppercase extension. Same shape as `1.14`'s misnamed
bindparam — correct-looking at every individual site, wrong only in the relationship between them.

## Two things that are NOT green and are filed rather than buried

1. **`run_strategist.failed`** — `"Could not resolve authentication method. Expected one of api_key,
   auth_token, or credentials to be set"`. `ANTHROPIC_API_KEY` is in `.env` (so in `Settings`) but not
   in `os.environ`, and the Anthropic client reads `os.environ`. **Exactly the `1.13` gotcha.** Worse:
   `synthesize_retrieval_strategy` then logged **`.complete` and the task `succeeded`** — a swallowed
   failure that reports success. Filed as `1.28`.
2. **A green E2E-2 against MinIO proves the ingestion chain, not AWS S3 compatibility.** MinIO is not
   S3. Nothing here has spoken to a real AWS endpoint, and the seam that made this possible is refused
   in production by design, so the production path remains unexercised.
