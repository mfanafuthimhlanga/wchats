## What changed

**`_fetch_eval_summary_sync` gained a fifth state.** It reads
`eval_runs.config["agent_invoked"]` — P2's write — and returns
`EVAL_SIGNAL_AGENT_NOT_INVOKED` when the claim is anything other than `True`,
with `pass_rates` suppressed. Suppression matters more here than in the other
four states because this is the only one whose scores EXIST: letting 0.99
travel while the recommendation blocks would put "excellent answer quality" in
the owner-facing summary above a refusal.

**`apply_signal_evidence_gate` gained a fifth refusal**, `agent_invoked is not
True`, on any payload claiming 'measured'.

**Absent is refused exactly as false is** (settled by the owner, 2026-08-07).
Every eval run persisted before this branch was produced by the tautology at
`eval.py:374-375` and carries no such key, so `is False` would have refused
nothing that exists — BACKLOG `3.1`'s shape.

**Accepted cost, live from this commit:** every pre-D1 run, and every tenant DB
older than `alembic_tenant` 0013 (no `config` column at all), fails closed until
that DB is re-migrated and a fresh eval runs.

## Deviations from the plan

**No migration, and that is a finding rather than an omission.** P3's plan
section assumed `agent_invoked` was a new column. P2 put it inside
`eval_runs.config`, the JSONB 0013 already added, so there is no DDL to write. A
dedicated column would give the one gate-facing claim a second home to disagree
from — what `eval_service.invocation_provenance`'s docstring exists to prevent —
and a backfill stamping `false` onto history would change no outcome, because
absent and false are refused identically. `0015` remains the tenant head;
`git diff 65eab9e HEAD -- apps/api/alembic_tenant/` is empty.

**Scores suppressed, not merely blocked.** Not in the plan. The plan asked for a
gate that refuses; suppressing the tautology's numbers as well is the half that
stops the orchestrator narrating "answer quality is excellent" above the
refusal (BACKLOG `5.4`, one layer down).
