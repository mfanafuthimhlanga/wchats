<objective>
Wire the validation chain into run_agent_turn. After the agent.response event is emitted
and committed, dispatch run_gatekeeper → run_auditor → run_strategist as a Celery chain of
immutable signatures (chord is broken on the solo pool). Also close the real gap found
during planning: _run_sdk_turn currently records only {tool_name, input} per tool call and
discards the ToolResultBlock content — so the Auditor would have no retrieved context to
ground against (RESEARCH Pitfall 3 / Assumption A2). This plan captures the retrieve tool
result into tool_calls_log and builds a truncated retrieved_context_json for the Auditor.

Purpose: VAL-04 (validators run async after the response is streamed) and VAL-02 (Auditor
checks claims against retrieved context) both depend on this dispatch + context capture.
The user already has their response before any validator runs.

Output: A modified agent.py (capture + dispatch) and an updated test asserting the chain is
dispatched with the correct signatures only on the success path.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Agent turn → validator chain (via Redis) | response_text + user message + retrieved_context dispatched as task args; sensitive text but no secrets |
| SDK tool result → tool_calls_log | retrieve result content captured from the SDK subexecution; treated as data, truncated |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-04-01 | Denial of Service | Large retrieved_context inflating Redis task-arg size | mitigate | retrieved_context truncated to top-3 results, 600 chars each, before json.dumps; captured result also capped at 1800 chars in tool_calls_log |
| T-05-04-02 | Denial of Service | Chord deadlock on solo pool stalling the worker | mitigate | Use celery chain with immutable .si() signatures only; chord is forbidden (RESEARCH Pitfall 1) — acceptance asserts zero `chord(` occurrences |
| T-05-04-03 | Information Disclosure | conn_str or API keys leaking into validator task args | mitigate | Chain signatures pass only str primitives (agent_id, job_id, response_text, message, context, conversation_id); Auditor decrypts conn_str itself at runtime (CTL-08) |
| T-05-04-04 | Tampering | Validators dispatched for a turn that produced no response (idempotent-skip / failure) | mitigate | Dispatch placed strictly on the success branch after agent.response emit + commit; test asserts no dispatch on idempotency-skip path |
</threat_model>
