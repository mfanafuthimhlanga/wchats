<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| adapter → Stripe API | outbound TLS call to fixed Stripe endpoints (no user-controlled URL) |
| CredentialHandle → StripeClient | the only place the raw key is read; localized to the sync closure |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-16-01 | Information Disclosure | api_key in logs | mitigate | key read only via handle.use() inside the closure; structlog calls log only skill/status/ids (acceptance criterion) |
| T-16-02 | Tampering | SSRF via adapter URL | mitigate | Stripe SDK targets fixed Stripe endpoints; no URL field in typed schemas; success/cancel URLs are static placeholders, not from tool args |
| T-16-08 | Replay | idempotency key reuse | mitigate | args.idempotency_key forwarded to Stripe native Idempotency-Key; Stripe returns the original response on replay (defense-in-depth atop the W Chats idempotency engine) |
| T-16-03 | Elevation of Privilege | over-scoped Stripe key | transfer | Per-tenant Stripe Restricted API Key scoped to enabled skills is provisioned at deploy time (Plan 16-07); adapter assumes a correctly-scoped key |
| T-16-cur | Tampering | currency override via args | mitigate | currency is always self._currency_code from credential config, never from args (INT-07, test_currency_from_config_not_args) |
</threat_model>
