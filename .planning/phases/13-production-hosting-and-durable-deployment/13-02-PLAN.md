<objective>
Move BOTH the document-embedding path (`embedding_service.embed_chunks`) and the query-embedding path (`retrieval_service.embed_query`) onto Amazon Bedrock **Titan Text Embeddings v2** (`amazon.titan-embed-text-v2:0`, 1024-dim) behind a config-driven provider seam, with the existing Voyage client retained only as a fallback behind the same interface. This is the **correctness gate** of PROD-06: research proved that moving only the query side is mathematically broken — query and document vectors must come from the same model or cosine similarity is meaningless. The corpus re-embed/backfill that follows from this swap is plan 13-04.

This is **ROADMAP Wave 1 (managed embeddings tier)**.

Purpose: Remove the Voyage `voyage-3` 3 RPM free-tier ceiling permanently via IAM-authed Bedrock, while keeping the `VECTOR(1024)` HNSW schema unchanged (Titan v2 @1024-dim matches exactly — no migration).
Output: A `bedrock_embedding_service` module, a provider seam in `config.py`, swapped document/query paths, and unit tests proving 1024-dim + correct model id + dimension guard.
</objective>
