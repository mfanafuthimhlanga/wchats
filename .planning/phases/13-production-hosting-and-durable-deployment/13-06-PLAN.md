<objective>
Move document uploads off local disk (`UPLOADS_DIR`, default `/vrd-uploads`) onto S3 so uploads survive worker restarts and are reachable from any Fargate task, and make the ingestion chain read source bytes from S3 with no local-disk dependency anywhere (PROD-12, PROD-13). A new `storage_service` centralises the boto3 S3 client; uploads write to a tenant-scoped key `{agent_id}/{doc_id}{ext}`; the parse task reuses the existing `parse_document_from_bytes()` (already used for URL sources — no Docling change); and the hardcoded `/vrd-uploads` cleanup in `embed.py` is corrected.

This is **ROADMAP Wave 3 (object storage for uploads)** — the code change (the uploads bucket + IAM already exist in the Terraform from 13-01). The live upload→S3→parse smoke is 13-10 (autonomous: false).

Purpose: Local-disk uploads break the moment a request and its ingestion run on different Fargate tasks; S3 with tenant-scoped keys is the durable, multi-task-reachable replacement.
Output: `storage_service`, an `S3_UPLOADS_BUCKET` env seam, S3 put on upload, S3 get → `parse_document_from_bytes` on parse, the embed.py cleanup corrected, and unit tests with boto3 stubbed.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Client upload → S3 | File bytes cross from the authenticated tenant request into a private, tenant-scoped S3 key |
| Pipeline task → S3 | Server-side boto3 get_object inside Fargate via IAM task role |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-13-06-01 | Elevation of Privilege | Cross-tenant S3 key guessing | mitigate | Keys are scoped by agent UUIDv4 prefix (~122-bit entropy); bucket is private (Block Public Access from 13-01); IAM task role scoped to the uploads bucket |
| T-13-06-02 | Information Disclosure | Public/presigned exposure of uploads | mitigate | Server-side boto3 get_object only (IAM task role); no presigned public URL; bucket not world-readable |
| T-13-06-03 | Tampering | Local-disk dependency breaks across tasks | mitigate | All upload/parse I/O moves to S3; no UPLOADS_DIR read/write on the hot path |
| T-13-06-04 | Information Disclosure | File bytes / conn_str in logs | mitigate | Logs reference doc_id/agent_id only; never bytes or conn_str |
</threat_model>
