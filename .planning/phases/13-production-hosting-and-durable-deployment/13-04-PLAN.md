<objective>
Author the one-time, per-tenant **re-embed / backfill** Celery task that realigns the existing Voyage `voyage-3` corpus onto Amazon Bedrock Titan v2 so query and document vectors share one embedding space (the correctness completion of PROD-06 begun in 13-02). The task is `acks_late=True`, idempotent, resumable, and strictly tenant-isolated, and it re-indexes the HNSW index on the Neon direct endpoint after backfill.

This is **ROADMAP Wave 1 (one-time re-embed/backfill)**. This plan authors the task + tests; the live per-tenant run against Bedrock and the retrieval-quality regression check happen in 13-08 (autonomous: false).

Purpose: Without this backfill, the 13-02 Bedrock query embedder would compute cosine similarity against Voyage-embedded document vectors — meaningless results, silently wrong retrieval. The backfill upserts Bedrock vectors over the same `embeddings.vector VECTOR(1024)` rows (Titan v2 @1024 matches; no schema change).
Output: `reembed_corpus(agent_id)` in the pipeline queue, registered in celery_app, with unit tests proving idempotency, tenant isolation, and ON CONFLICT upsert.
</objective>
