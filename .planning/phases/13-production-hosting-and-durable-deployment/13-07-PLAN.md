<objective>
Make the runtime worker concurrency-safe and run it at concurrency > 1. Refactor the seven module-level globals in `agent_tools.py` (`_conn_str`, `_agent_id`, `_agent_name`, `_strategy`, `_conversation_id`, `_notify_fn`, `_retrieve_call_count`) to `ContextVar`s so a worker running multiple tasks carries no cross-request state bleed (PROD-14); make `celery_app.worker_pool` `ENVIRONMENT`-conditional and bump the Fargate runtime command to `--pool=prefork --concurrency=2` (PROD-15); and lift the Voyage-era 2-retrieve-per-turn throttle now that embeddings are on Bedrock (PROD-06 throttle removal).

This is **ROADMAP Wave 4 (horizontal worker scaling)** — the code change. The live concurrent-load verification is 13-11 (autonomous: false). PROD-15 depends on this PROD-14 refactor landing first (CONTEXT must-shape #3), and the ContextVar-across-`asyncio.run` propagation is verified BEFORE the full refactor (CONTEXT must-shape #8).

Purpose: With `worker_pool="solo"`, the module globals are safe only because tasks run one-at-a-time. To deliver real concurrency the state must be per-task-isolated; ContextVar is the locked, future-proof mechanism. The retrieve cap existed solely for the Voyage 3 RPM free tier — Bedrock removes that ceiling.
Output: ContextVar-based tool state, an ENVIRONMENT-conditional worker pool + prefork/concurrency=2 Fargate command, the lifted throttle, and a concurrency-isolation + asyncio.run-propagation unit test.
</objective>
