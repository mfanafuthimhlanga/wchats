**One-liner:** Per-IP 10/min rate limit on JWT-mint config endpoint and per-agent 50-slot SSE cap with 120s asyncio.timeout hard cutoff, both backed by Redis and verified with 5 new security tests.

## What Was Built

### Task 1: F2 — Per-IP Config Rate Limit

**Problem:** `GET /widget/{agent_id}/config` minted a fresh JWT on every call with no per-IP throttle, enabling unlimited JWT harvest and cost-bomb attacks.

**Implementation:**

- Added `asyncio` and `from redis.asyncio import Redis` imports to widget.py
- Added `_check_config_rate_limit(agent_id, client_ip, redis)` async helper:
  - Key: `rate:config:{client_ip}:{bucket}` where `bucket = int(time.time()) // 60`
  - Redis INCR + 120s TTL + ceiling 10 → HTTP 429 with `Retry-After: 60`
  - Logs `debug` warning if `X-Forwarded-For` header present (trusts `request.client.host` in M4.1)
- Updated `get_widget_config` signature: added `request: Request` and `redis_client=Depends(get_async_redis)`
- Rate limit called as first line of handler body before any DB access or JWT mint

**Tests added:**
- `test_widget_config_rate_limited_by_ip` — mock redis.incr returns 11 → asserts 429 + Retry-After: 60
- `test_widget_config_different_ips_not_affected` — mock redis.incr returns 1 → asserts 200

**Regression fix:** Existing `TestWidgetConfig200` and `TestWidgetConfig404` tests updated to provide `mock_redis` dependency override (config endpoint now requires Redis).

### Task 2: F8 — SSE Concurrent Connection Cap

**Problem:** `GET /widget/jobs/{job_id}/events` had no concurrent connection cap (connection exhaustion DoS) and no hard timeout (hung connections).

**Implementation:**

- Added `_MAX_CONCURRENT_SSE_PER_AGENT = 50` module-level constant
- Added `_acquire_sse_slot(agent_id, job_id, redis)` async helper:
  - SETNX `sse:slot:{agent_id}:{job_id}` with 150s TTL (atomic slot claim)
  - INCR `sse:count:{agent_id}` with 3600s TTL
  - If count > 50: deletes slot, decrements count, returns `False`
- Added `_release_sse_slot(agent_id, job_id, redis)` async helper:
  - Deletes slot key, decrements count if deletion was successful
- Rewrote `widget_job_events` handler:
  1. DB lookup: `select(Job).where(Job.id == job_id)` → raises 404 if not found
  2. `_acquire_sse_slot` → raises 503 if `False`
  3. Inner `_wrapped_generator()` with `asyncio.timeout(120)`, catches `TimeoutError`, `finally` calls `_release_sse_slot`
  4. Returns `EventSourceResponse(_wrapped_generator())` with existing CORS/cache headers

**Tests added:**
- `test_sse_slot_acquired_and_released` — mocks acquire=True, asserts both helpers called once
- `test_sse_returns_503_when_agent_at_capacity` — mocks acquire=False, asserts 503 response
- `test_sse_hard_timeout_fires` — directly drives `_wrapped_generator` pattern with 0.05s timeout, asserts TimeoutError caught + release called in finally

**Regression fix:** `TestWidgetJobEvents` updated to mock DB Job row lookup and patch slot helpers.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Existing config tests broke after adding redis_client dependency**
- **Found during:** Task 1 GREEN phase
- **Issue:** `TestWidgetConfig200` and `TestWidgetConfig404` did not override `get_async_redis`, so adding that dependency to `get_widget_config` caused them to try to connect to real Redis (refused connection error)
- **Fix:** Added `mock_redis = _make_mock_redis(incr_return_value=1)` and `app.dependency_overrides[get_async_redis] = lambda: mock_redis` to both tests
- **Files modified:** `apps/api/tests/unit/test_widget_routes.py`
- **Commit:** 6be2643

**2. [Rule 1 - Bug] Existing TestWidgetJobEvents broke after adding Job DB lookup to widget_job_events**
- **Found during:** Task 2 GREEN phase
- **Issue:** `TestWidgetJobEvents` used a bare `AsyncMock()` for DB — no Job row returned — so adding the `select(Job)` lookup caused the handler to return 404
- **Fix:** Updated test to build a mock Job row with `agent_id` and mock `db.execute` to return it; added patches for `_acquire_sse_slot` and `_release_sse_slot`
- **Files modified:** `apps/api/tests/unit/test_widget_routes.py`
- **Commit:** 6d345f5

**3. [Rule 1 - Bug] test_sse_hard_timeout_fires: asyncio.timeout patch approach caused infinite recursion**
- **Found during:** Task 2 RED/GREEN iteration
- **Issue:** First approach patched `asyncio.timeout` with an `@asynccontextmanager` that itself called `asyncio.timeout` — but since the module reference was patched, this recursed infinitely
- **Fix:** Redesigned test to directly test the `_wrapped_generator` pattern (not via HTTP) using real `asyncio.timeout` with a tiny 0.05s delay on the inner generator
- **Files modified:** `apps/api/tests/unit/test_widget_routes.py`
- **Commit:** 6d345f5
