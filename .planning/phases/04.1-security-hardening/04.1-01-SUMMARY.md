## What Was Built

### F1 — Column-Name SQL Injection Fix (CRITICAL)

- Added `_ALLOWED_FILTER_COLUMNS` dict with per-table frozensets: `chunks` (id, document_id, section, chunk_order), `documents` (id, name, parse_status, source_uri), `chunk_metadata` (chunk_id, entity_type, entity_value).
- Added `_validate_filter_columns(table, filters)` helper returning list of rejected column names.
- Replaced the f-string injection site (`f"{col} = %s"` at old line 225) with:
  1. Allowlist check: `rejected = _validate_filter_columns(table, filters)` — early return with `is_error=True` if any column rejected.
  2. `from psycopg2 import sql as pgsql` (inside function body per CONTEXT.md lock).
  3. `pgsql.SQL("{} = %s").format(pgsql.Identifier(col))` for all WHERE clause fragments.
  4. Full SQL assembled as `pgsql.SQL(...)` objects, not f-strings.

### F3 — Escalation Idempotency + Sanitisation (HIGH)

- Added `_CONTROL_CHAR_RE = re.compile(r"[\x00-\x1f\x7f]")` module-level regex.
- Added `_sanitise_escalation_field(value, max_len=500)` helper.
- Rewrote `_mark_conversation_escalated` with new `agent_id` parameter and idempotency SQL:
  `WHERE id = %s AND agent_id = %s AND (metadata->>'escalated') IS DISTINCT FROM 'true'`
- Returns `{"already_escalated": True}` when `cur.rowcount == 0`.
- Updated `escalate_to_human_tool` to: sanitise reason/context, check `already_escalated` before calling `_notify_fn`, and prefix notification with `[AGENT-DETECTED — UNVERIFIED]`.

### F7 — Filters No-Op Warning (MEDIUM)

- Added `filters = args.get("filters", [])` extraction in `retrieve_tool`.
- Emits `log.warning("retrieve_tool.filters_ignored", filter_count=..., conversation_id=..., note=...)` when `filters` is non-empty.
- Comment references AR-03-07 / TODO-RET-01 for future enforcement tracking.
