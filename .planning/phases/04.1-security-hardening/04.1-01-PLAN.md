<objective>
Harden agent_tools.py against three security findings:

F1 (CRITICAL): Column-name SQL injection. LLM-supplied filter keys are currently
f-string interpolated at line 225. Add a two-layer defence: a per-table column
allowlist (_ALLOWED_FILTER_COLUMNS) that blocks and logs unknown columns BEFORE
any SQL assembly, plus psycopg2.sql.Identifier quoting as a belt-and-suspenders
structural layer.

F3 (HIGH): Escalation tool spam via indirect prompt injection. Add SQL idempotency
guard (WHERE ... IS DISTINCT FROM 'true'), sanitise reason/context fields to
strip control characters and enforce 500-char cap, prefix notification payloads
with [AGENT-DETECTED — UNVERIFIED].

F7 (MEDIUM): filters parameter is a no-op but silently accepted. Add a structlog
WARNING in retrieve_tool whenever LLM-supplied filters are present, making any
future silent activation loudly visible in observability.

Purpose: These three findings share the same target file and are safe to implement
in parallel (Wave 1). F1 and F3 close CRITICAL and HIGH attack chains that enable
SQL injection and notification abuse from poisoned documents.

Output: Modified agent_tools.py with hardened lookup_structured_tool and
escalate_to_human_tool; extended test_agent_tools.py with 7 new security tests.
</objective>
