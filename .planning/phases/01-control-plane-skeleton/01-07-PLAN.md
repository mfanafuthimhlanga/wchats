  test_worker_kill_9_chain_completes (mark: integration):
  This test starts a real Celery worker process, triggers the chain, kills the worker during provision_neon after the project.ready event but before apply_migrations starts, restarts the worker, and asserts the chain completes.

  Implementation approach:
  1. Use subprocess.Popen to start celery worker: celery -A app.worker.celery_app worker --queues=pipeline --concurrency=1 --loglevel=info
  2. Wait for worker to be ready (poll celery inspect ping or wait 3s)
  3. Create tenant/agent/job rows in real Postgres
  4. Dispatch chain: provision_neon.apply_async((tenant_id, agent_id), queue="pipeline") with respx mock for Neon API
  5. Wait for neon.project.ready event in job_events (poll DB every 0.5s, timeout 30s)
  6. Kill worker: os.kill(worker_proc.pid, signal.SIGKILL)
  7. Wait 1s for kill to complete
  8. Restart worker: same subprocess.Popen
  9. Wait for job.complete in job_events (poll DB every 1s, timeout 60s)
  10. Fetch agent from DB: assert agent.status == "ready"
  11. Assert agent.neon_project_id is set
  12. Assert agent.schema_version is set
  13. Cleanup: terminate worker process

  Note: This test requires docker-compose Postgres and Redis to be running. Mark it with @pytest.mark.integration and skip automatically if DB is not available (use pytest.importorskip or a fixture that checks connectivity).
