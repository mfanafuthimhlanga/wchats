## Objective

Create the Pydantic schema file for red team API responses, implement three FastAPI routes (GET list, GET detail, POST trigger) for red team run management, and register the router in `main.py`. All routes follow the exact patterns established in `apps/api/app/api/v1/evals.py` — same auth dependency, same IDOR check, same psycopg2-via-asyncio.to_thread pattern for tenant DB queries, same 202 dispatch pattern for the trigger route.

- acks_late=True AND idempotency guard on every Celery task
- conn_str never in Celery task args — fetch from control DB by agent_id at runtime
- asyncio.run() bridge in Celery tasks (never loop.run_until_complete)

    Module docstring: "Pydantic schemas for M7 red team API routes — request/response models for red_team_runs endpoints."

    Imports: `from __future__ import annotations`, `from datetime import datetime`, `from typing import Any`, `from pydantic import BaseModel`.

    1. `RedTeamRunResponse(BaseModel)`:
       - `id: str`
       - `kind: str`
       - `status: str`
       - `started_at: datetime | None`
       - `finished_at: datetime | None`

       - `deployment_blocked: bool`

    2. `RedTeamRunListResponse(BaseModel)`:
       - `runs: list[RedTeamRunResponse]`

    3. `RedTeamTriggerRequest(BaseModel)`:
       - No fields — empty body is acceptable (manual trigger has no parameters)

    4. `RedTeamTriggerResponse(BaseModel)`:
       - `job_id: str`    — the Celery task ID
       - `run_id: str`    — placeholder (actual run_id assigned inside the task; return the task_id here as a correlator)
       - `message: str`   — human-readable status message, e.g., "Red team run queued"

    Module docstring: "Red team routes for Veridian M7. Queries tenant DB (red_team_runs) for run history and per-run findings. All routes require X-API-Key auth via get_current_tenant. IDOR prevented by verifying agent.tenant_id == tenant.id. Routes: GET list, GET detail, POST trigger."

    ```python
    from app.models.tenant import Tenant

    ```

    ```python
    router = APIRouter(tags=["red_team"])
    log = structlog.get_logger(__name__)
    ```

    **Internal helper (same as evals.py):**
    ```python
    def _query_tenant_db_sync(conn_str: str, sql: str, params: dict) -> list[tuple]:
    ```
    Uses `psycopg2.connect(conn_str, connect_timeout=10)`, executes `cur.execute(sql, params)`, returns `cur.fetchall()`, always closes connection in `finally`.

    **Route 1: GET /agents/{agent_id}/red-team-runs**

    SQL constant `_LIST_RED_TEAM_RUNS_SQL`:
    ```sql
    SELECT id, kind, status, started_at, finished_at, findings, max_severity, deployment_blocked
    FROM red_team_runs
    ORDER BY started_at DESC
    LIMIT 20
    ```

    Decorator: `@router.get("/agents/{agent_id}/red-team-runs")`
    Signature: `async def list_red_team_runs(agent_id: UUID, db: AsyncSession = Depends(get_async_db), tenant: Tenant = Depends(get_current_tenant)) -> dict:`

    Steps (same pattern as `list_eval_runs` in evals.py):
    1. `agent = await db.get(Agent, agent_id)` — raise 404 if None
    2. Check `agent.tenant_id != tenant.id` — raise 404 if mismatch (IDOR prevention)
    3. Check `not agent.neon_connection_string` — raise 404 "Agent database not provisioned"
    4. `conn_str = fernet_decrypt(agent.neon_connection_string)` — never log conn_str
    5. `rows = await asyncio.to_thread(_query_tenant_db_sync, conn_str, _LIST_RED_TEAM_RUNS_SQL, {})`
    6. Build response: for each row `(id, kind, status, started_at, finished_at, findings, max_severity, deployment_blocked)`, construct a dict matching `RedTeamRunResponse` fields. `findings` from psycopg2 is already a Python list (JSONB auto-parsed) — if None, use `[]`. `deployment_blocked` may be None for old rows — default to `False`.
    7. Log `log.info("list_red_team_runs.ok", agent_id=str(agent_id), tenant_id=str(tenant.id), run_count=len(runs))`
    8. Return `{"runs": runs}` where `runs` is the list of dicts

    **Route 2: GET /agents/{agent_id}/red-team-runs/{run_id}**

    SQL constant `_GET_RED_TEAM_RUN_SQL`:
    ```sql
    SELECT id, kind, status, started_at, finished_at, findings, max_severity, deployment_blocked
    FROM red_team_runs
    WHERE id = %(run_id)s
    ```

    Decorator: `@router.get("/agents/{agent_id}/red-team-runs/{run_id}")`
    Signature: `async def get_red_team_run(agent_id: UUID, run_id: UUID, db: AsyncSession = Depends(get_async_db), tenant: Tenant = Depends(get_current_tenant)) -> dict:`

    Steps:
    1–4. Same agent fetch + IDOR check + conn_str decrypt as Route 1.
    5. `rows = await asyncio.to_thread(_query_tenant_db_sync, conn_str, _GET_RED_TEAM_RUN_SQL, {"run_id": str(run_id)})`
    6. If `not rows`, raise `HTTPException(status_code=404, detail="Red team run not found")`
    7. Build and return a single run dict from `rows[0]` with the same field mapping as Route 1
    8. Return `{"run": run_dict}`

    **Route 3: POST /agents/{agent_id}/red-team-runs**

    Decorator: `@router.post("/agents/{agent_id}/red-team-runs", status_code=202)`
    Signature: `async def trigger_red_team_run(agent_id: UUID, db: AsyncSession = Depends(get_async_db), tenant: Tenant = Depends(get_current_tenant)) -> dict:`

    Steps (same pattern as `trigger_eval_run` in evals.py):
    1. Fetch agent + IDOR check (same as other routes)
    2. Check `agent.status != "ready"` — raise `HTTPException(status_code=400, detail="Agent must be in ready state to run red team")`
    3. Dispatch: `task = run_red_team.apply_async(kwargs={"agent_id": str(agent_id)}, queue="runtime")`
    4. Log `log.info("red_team_trigger.dispatched", agent_id=str(agent_id), task_id=task.id, tenant_id=str(tenant.id))`
    5. Return `{"job_id": task.id, "run_id": task.id, "message": "Red team run queued"}` — note that `run_id` is populated with `task.id` as a correlator at dispatch time (the actual DB `run_id` is generated inside the task)
