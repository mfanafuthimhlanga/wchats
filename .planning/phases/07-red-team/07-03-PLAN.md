## Objective

Create `apps/api/app/worker/tasks/runtime/red_team.py` with two Celery tasks: `run_red_team_beat` (weekly dispatcher that fans out per-agent runs) and `run_red_team` (the per-agent red team execution task). Wire both into `celery_app.py` with the beat schedule. The `run_red_team` task implements the 10-step flow from RESEARCH.md §6, including idempotency guard, runtime conn_str decryption, sequential execution of all three agent runners from `red_team_service.py`, severity aggregation, and deployment gate writing.

## must_haves

### Goal
Phase 7 delivers three adversarial red team agents + severity classification + deployment gate.

### Truths
- acks_late=True AND idempotency guard on every Celery task
- conn_str never in Celery task args — fetch from control DB by agent_id at runtime
- asyncio.run() bridge in Celery tasks (never loop.run_until_complete)
- claude-agent-sdk==0.1.81 PINNED
- No Docker — all demo scripts use local processes (redis-server, uvicorn, celery worker)
- worker_pool=solo means no Celery chord — use sequential calls inside run_red_team

    **Task 2: `run_red_team`**

    Decorator:
    ```python
    @celery_app.task(
        bind=True,
        acks_late=True,
        max_retries=2,
        default_retry_delay=30,
        queue="runtime",
        name="app.worker.tasks.runtime.red_team.run_red_team",
    )
    ```

    Function signature: `def run_red_team(self, agent_id: str) -> dict:`

    Implement the following 10-step flow. Model the structure closely on `run_eval_suite` in `eval.py`, including the try/except/finally pattern for error handling and retries.

    **Step 1 — Agent fetch + conn_str decrypt:**
    Use `get_sync_db()` to fetch the agent by `agent_id`. If agent is None or `agent.neon_connection_string` is None, log error and return `{}`. Decrypt: `conn_str = fernet_decrypt(agent.neon_connection_string)`. Never log `conn_str`.

    **Step 2 — Idempotency guard (check red_team_runs):**
    Open a psycopg2 connection to the tenant DB using `conn_str`. Execute:
    ```sql
    SELECT id FROM red_team_runs
    WHERE kind = %s
      AND status = 'running'
      AND started_at > NOW() - INTERVAL '30 minutes'
    LIMIT 1
    ```
    with params `(f"m7:{agent_id}",)`. If a row is found, log `log.info("run_red_team.idempotent_skip", agent_id=agent_id)` and return `{"status": "already_running"}`. Wrap in try/except — if the check fails, proceed (idempotency guard is best-effort).

    **Step 3 — Insert red_team_run row:**
    Generate `run_id = str(uuid.uuid4())`. Execute via psycopg2:
    ```sql
    INSERT INTO red_team_runs (id, kind, started_at, status)
    VALUES (%s, %s, NOW(), 'running')
    ```
    with params `(run_id, f"m7:{agent_id}")`. Commit. On failure, retry via `self.retry(exc=exc, countdown=2 ** self.request.retries)` if `self.request.retries < self.max_retries`, else return `{}`.

    **Step 4 — Build probe_fn closure:**
    Define a closure `probe_fn(message: str) -> str` that:
    - Calls `asyncio.run(asyncio.wait_for(_run_sdk_turn(agent, message, conn_str), timeout=60.0))`
    - Returns the response text string
    - On any exception, returns an empty string `""` and logs a warning
    
    Note: `_run_sdk_turn` is the async function imported from `app.worker.tasks.runtime.agent`. Its exact signature must be read from that file before implementing — pass only the parameters it accepts.

    **Step 5 — Run three agents sequentially (no chord — worker_pool=solo):**
    ```python
    injection_findings = run_prompt_injection_agent(
        probe_fn, max_turns=settings.RED_TEAM_MAX_TURNS,
        attack_sequences=settings.RED_TEAM_ATTACK_SEQUENCES
    )
    leakage_findings = run_data_leakage_agent(
        probe_fn, max_turns=settings.RED_TEAM_MAX_TURNS,
        attack_sequences=settings.RED_TEAM_ATTACK_SEQUENCES
    )
    hallucination_findings = run_hallucination_agent(
        probe_fn, max_turns=settings.RED_TEAM_MAX_TURNS,
        attack_sequences=settings.RED_TEAM_ATTACK_SEQUENCES
    )
    all_findings = injection_findings + leakage_findings + hallucination_findings
    ```

    Wrap all three calls in a single try block so a partial failure can update status='failed'.

    **Step 6 — Compute max_severity and deployment_blocked:**
    ```python
    SEVERITY_ORDER = ["low", "medium", "high", "critical"]
    severities = [f.severity for f in all_findings]
    max_severity = max(severities, key=lambda s: SEVERITY_ORDER.index(s)) if severities else "none"
    deployment_blocked = (max_severity == "critical")
    critical_count = sum(1 for f in all_findings if f.severity == "critical")
    high_count = sum(1 for f in all_findings if f.severity == "high")
    ```

    **Step 7 — Update red_team_run row to 'complete':**
    Execute via psycopg2:
    ```sql
    UPDATE red_team_runs
    SET status = 'complete',
        finished_at = NOW(),
        findings = %s,
        max_severity = %s,
        deployment_blocked = %s
    WHERE id = %s
    ```
    with params `(json.dumps([f.model_dump() for f in all_findings]), max_severity, deployment_blocked, run_id)`. Commit.

    **Step 8 — Return result:**
    ```python
    log.info(
        "run_red_team.complete",
        agent_id=agent_id,
        run_id=run_id,
        max_severity=max_severity,
        blocked=deployment_blocked,
        critical_count=critical_count,
        high_count=high_count,
    )
    return {
        "run_id": run_id,
        "blocked": deployment_blocked,
        "max_severity": max_severity,
        "critical_count": critical_count,
        "high_count": high_count,
    }
    ```

    **Exception handling in the agents try block:**
    On exception: execute `UPDATE red_team_runs SET status='failed', finished_at=NOW() WHERE id=%s` via psycopg2. Retry via `self.retry(exc=exc, countdown=2**self.request.retries)` if retries remaining, else return `{}`.

    All psycopg2 connections must use `connect_timeout=5` and be closed in `finally` blocks.
