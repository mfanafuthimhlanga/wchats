<objective>
Add Clerk as the authentication backbone for the Veridian platform. Admin UI routes are
protected by clerkMiddleware(). FastAPI deps accept Clerk session JWTs (RS256 via JWKS)
on the Authorization header, falling back to X-API-Key for legacy tenants. Tenant rows
are auto-provisioned from a Clerk webhook (user.created) and a self-healing
POST /me/provision endpoint. The soul editor replaces the sessionStorage API key hack
with Clerk's getToken().

Purpose: M4 must be a hireable artifact. A production-ready system requires real
authentication — not a hardcoded API key stored in sessionStorage. Clerk provides
OAuth/social login, MFA, session management, and webhook-based provisioning without
building any of that infrastructure. The dual-auth fallback means existing tenants are
not broken.

Output: Alembic migration 0005, new core/clerk_jwt.py module, updated deps.py (dual
auth), new webhooks.py router (POST /webhooks/clerk + POST /me/provision), updated
Tenant ORM and Settings, updated pyproject.toml, updated admin UI (middleware, layout,
soul page), and unit tests covering all auth paths.
</objective>

verify_clerk_jwt module (NEW — apps/api/app/core/clerk_jwt.py):
  from functools import lru_cache
  import jwt
  from jwt import PyJWKClient, InvalidTokenError
  from app.core.config import settings

  @lru_cache(maxsize=1)
  def _get_jwks_client() -> PyJWKClient:
      return PyJWKClient(settings.CLERK_JWKS_URL, cache_keys=True, lifespan=3600)

  def verify_clerk_jwt(token: str) -> dict:
      client = _get_jwks_client()
      signing_key = client.get_signing_key_from_jwt(token)
      payload = jwt.decode(
          token,
          signing_key.key,
          algorithms=["RS256"],
          options={"verify_exp": True, "verify_nbf": True, "verify_aud": False},
      )
      return payload
      # Wrap all exceptions in InvalidTokenError (re-raise)
