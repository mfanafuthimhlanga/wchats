Eval scenario schema (AI-SPEC.md §5.3):
  {
    "id": "S-NNN",
    "category": "golden_path" | "edge" | "adversarial" | "out_of_scope",
    "description": "<one sentence>",
    "tenant_fixture": "fixtures/demo_business_tenant.sql",
    "turns": [ { "role": "user", "message": "..." }, ... ],
    "expected_behavior": {
      "retrieve_called": bool,
      "citation_present": bool,
      "escalated": bool,
      "knowledge_gap_acknowledged": bool
    },
    "human_verdict": "PASS" | "FAIL",
    "human_label_notes": "...",
    "deterministic_checks": {                    # optional — only for D5/D6/D7-tied scenarios
      "D5": {"regex": "CITATIONS:\\n- Document: .+ \\| Section: .+"},
      "D6": {"expected_tool": "retrieve", "max_clarify": 2, "max_escalate": 1, "allowed_tables": ["chunks","documents","chunk_metadata"]}
    }
  }

Eight evaluation dimensions (AI-SPEC.md §5.1):
  D1 Grounding fidelity        — LLM judge
  D2 Escalation accuracy       — LLM judge
  D3 Prompt injection resistance — LLM judge (regex check augments)
  D4 Session continuity        — LLM judge + deterministic conversation_id check
  D5 Citation format compliance — DETERMINISTIC regex
  D6 Tool call correctness      — DETERMINISTIC assertion on tool_calls log
  D7 Widget bundle size         — DETERMINISTIC zlib gzip check (Plan 05 enforces in postbuild)
  D8 Knowledge gap honesty      — LLM judge

Judge model contract (AI-SPEC.md §5.2):
  Model: claude-sonnet-4-5-20251001 (NOT haiku — would bias toward agent's own reasoning)
  Direct anthropic client (NOT Agent SDK)
  Returns ONLY JSON {dimension, verdict, score, reason}
  Judge never receives the agent's system_prompt — only transcript + retrieved chunks + tool_calls_log

run_evals.py contract:
  Modes:
    - Deterministic-only (default): runs D5/D6 regex+assertion checks on a stub or recorded conversation; no LLM calls, no ANTHROPIC_API_KEY required, exits 0 on success
    - Full E2E (AGENT_E2E_ENABLED=1): also runs D1/D2/D3/D4/D8 via judge against real or fixture conversations
  Output: prints per-dimension pass/fail counts and aggregate pass_rate; non-zero exit code if any P0 dimension < 100% in E2E mode

Composition required (AI-SPEC.md §5.3):
  Golden path: 6 (S-001 through S-006)
  Edge cases: 5 (S-007 through S-011)
  Adversarial: 5 (S-012 through S-016)
  Out-of-scope / knowledge gap: 4 (S-017 through S-020)

demo_business_tenant.sql fixture:
  Bella Vista Coffee — minimal corpus: 6 documents (Return Policy, Hours, Product Catalog, Pricing, Contact Info, Shipping Policy), each with 1-3 chunks; matching chunk_metadata rows
  Uses fake embeddings (random or zero vector(1024)) — eval scenarios that exercise retrieval rely on mocked retrieval_service, not real Voyage calls; the SQL just keeps schema referentially consistent
