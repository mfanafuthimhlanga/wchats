## Objective

Create apps/api/app/services/scenario_service.py implementing two capabilities: (1) a Claude Haiku scenario generator that produces eval scenarios from tenant knowledge chunks (EVL-02); (2) a production conversation miner that turns Gatekeeper/Auditor-flagged responses into new eval scenarios (EVL-03). Both write to the tenant DB eval_scenarios table.

Function: generate_scenarios_from_chunks(chunks: list[dict], n: int = 5) -> list[dict]
  - Concatenate up to 5 chunk["content"] with "---" separators
  - Call ANTHROPIC_CLIENT.messages.create(model=HAIKU_MODEL, max_tokens=1024, system=..., messages=[...], tools=[SCENARIO_TOOL], tool_choice={"type":"tool","name":"submit_scenarios"})
  - Iterate response.content blocks; on block.type=="tool_use" and block.name=="submit_scenarios": extract block.input["scenarios"]
  - Attach retrieved_contexts=[c["content"] for c in chunks[:5]] to each scenario
  - Return list of dicts with keys: question, reference_answer, scenario_category, retrieved_contexts, source="generated"
  - Raise ValueError("No tool_use block returned by scenario generator") if no block found

Function: store_scenarios(scenarios: list[dict], tenant_conn_str: str) -> int
  - psycopg2.connect(tenant_conn_str) try/finally pattern
  - INSERT INTO eval_scenarios (id, source, question, reference_answer, retrieved_contexts, scenario_category, created_at) with ON CONFLICT DO NOTHING
  - retrieved_contexts bound as json.dumps(s.get("retrieved_contexts",[])) cast to %s::jsonb
  - Return count of inserted rows

Function: generate_eval_suite_for_agent(agent_id: str, tenant_conn_str: str, num_scenarios: int = 20) -> int
  - Fetch up to 100 chunks from tenant DB: SELECT content FROM chunks ORDER BY created_at DESC LIMIT 100
  - Compute batch_size = min(5, max(1, len(chunks) // max(1, num_scenarios // 5)))
  - Process in batches: call generate_scenarios_from_chunks(batch, n=5) per batch until num_scenarios reached
  - Call store_scenarios(all_scenarios, tenant_conn_str)
  - Return total scenario count
  - Log: log.info("scenario_service.suite_generated", agent_id=agent_id, count=total)

Function: _fetch_messages_for_conversation(tenant_conn_str: str, conversation_id: str) -> list[dict]
  - psycopg2 SELECT role, content FROM messages WHERE conversation_id = %(conv_id)s::uuid ORDER BY created_at ASC
  - Returns [{"role": row[0], "content": row[1]} for row in rows]

Function: mine_production_scenarios(agent_id: str, tenant_conn_str: str, control_db, lookback_hours: int = 168) -> list[dict]
  - Step 1: Query control_db for job_events WHERE event_type IN ('gatekeeper.complete','auditor.complete') AND payload->>'agent_id' = :agent_id AND payload->>'verdict' IN ('fail','ungrounded','partial') AND created_at > NOW() - INTERVAL ':hours hours' using sqlalchemy text() — extract DISTINCT job_id values.
  - Note: conversation_id is NOT in the job_events payload (it is a task arg in validators.py, not emitted). Use job_id to correlate: join job_events with jobs table WHERE jobs.id = job_events.job_id to get conversation context if available, else use job_id as a proxy key.
  - For each flagged result: attempt _fetch_messages_for_conversation if conversation_id is available; otherwise use payload question field.
  - Construct mined scenario: {"question": question, "reference_answer": "", "retrieved_contexts": [], "source": "mined", "scenario_category": "production_failure"}
  - Return list of mined dicts (may be empty if no flagged events in window)
  - Log: log.info("scenario_service.mined", agent_id=agent_id, count=len(mined))

Important: mined scenarios with reference_answer="" are stored but excluded from Ragas eval (ContextRecall and Faithfulness require reference). The run_eval_suite task filters scenarios with empty reference_answer before building the EvaluationDataset.
