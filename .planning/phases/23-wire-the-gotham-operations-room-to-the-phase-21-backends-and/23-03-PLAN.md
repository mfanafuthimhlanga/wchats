<objective>
Build the validation layer before the wiring, so the wiring lands against gates rather than
against hope. Two gates: a browserless pure-function layer that proves what a backend value
looks like on screen, and a static repository scan that proves each region actually calls its
endpoint and that the console makes no false claim about itself.

Purpose: WIRE-01, WIRE-02 and WIRE-03 shipped undetected through two phases that both passed
their own verification. Nothing in this repository could have caught them. The milestone
audit caught them by grepping. That grep becomes a permanent gate here.

Output: `opsFormat.ts` and its spec, a browserless runner config, and
`check-ops-room-wiring.mjs` in the shape of the shipped token gate.
</objective>

**Binding records:** `23-01-PLAN.md § Open Decisions Resolved`. **OD-6 governs this plan** —
no browser spec, no authentication short-circuit, and an explicit account of which gate
catches which defect.

    **Two sentinel constants and two checks.** Declare the two literals as named constants,

    helper makes it one keystroke to render a scan failure as an empty window.

    Each predicate narrows the type, so a caller that has passed the check cannot then hand
    the value to a numeric formatter without the compiler objecting. That type narrowing is
    the mechanical form of rule 1: a sentinel is never coerced into a number.

    **Formatters.** A percentage from a zero-to-one ratio; a score out of five; a millisecond
    figure; a dollars figure; a plain integer; a fixed-decimal score for the retrieval
    readings. Each takes a number and returns a string, and none of them accepts a union type
    — that is what forces the sentinel check to happen first at every call site.

    The dollars formatter carries a comment naming the trap: the per-session cost field is
    dollars, the shipped cents formatter in `deploy/page.tsx` divides by a hundred, and
    reusing it here would understate every cost by two orders of magnitude. Write the reason
    at the site; a future reader looking for a currency formatter will find the wrong one
    first otherwise.

    **Cell renderers.** Three functions, one per copy case, each taking the raw union value
    and returning the string to display: the live-metric case (interpolating the window in
    days that the metrics endpoint returns on its own payload), the retrieval-average case

    against `read_retrieval_health`'s return), and the staleness-failure case. The three
    locked sentences come from `23-UI-SPEC.md § 5` verbatim.

    **Derivations for the deploy gate.** A shape for an open finding matching Gap B's response

    the gate message. These are the pure half of WIRE-04's stale-verdict fix. Putting them here,
    in wave 1, means the correctness of the fix is provable before the component that consumes
    it exists — and it means a later edit that quietly reverts the gate to the frozen per-run
    snapshot has to delete a passing test to do it.

    and otherwise the generic sentence already shipped at `page.tsx:322`, which is copy the
    checker has already approved. It never returns an empty string and never returns the word

    **Verdict mappings.** The bench judge verdict to a chip verdict; the operator's grade to a

    **The canary percentage.** Absent and zero both render as a zero percentage. A version

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| backend response → rendered verdict | An operator decides whether an agent may serve customers based on what this layer renders. A sentinel shown as data, or data shown as absent, is a false verdict at the point of decision. |
| test tooling → production code | A gate that requires a production code path to exist only for its own benefit has moved a test concern across a trust boundary. |
| repository gate → build outcome | A gate that can be satisfied by a comment, or that scans itself, provides false assurance and is worse than no gate. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-23-VAL-01 | Spoofing | a gate satisfied by comment text | high | mitigate | The comment-stripping pass is copied from the shipped token gate and is demonstrated in both directions before this plan is done — a literal outside a comment must be named, the same literal inside one must not. Both observations are recorded. Without this, every explanatory comment this phase writes about what it deleted would trip the gate, and the reflex fix would be to weaken the gate. |
| T-23-VAL-02 | Spoofing | a gate that scans itself | medium | mitigate | Scan scope is the app directory only; the gate lives in the scripts directory and holds the forbidden literals. Asserted structurally, and it is the same self-exclusion the shipped token gate already relies on. |
| T-23-VAL-03 | Tampering | a sentinel string coerced into a number | high | mitigate | The formatters accept a number and only a number; the sentinel predicates narrow the type, so the compiler rejects a call that skipped the check.
