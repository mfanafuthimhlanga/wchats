<objective>
Give the Adversary region its real coverage table and the contain trigger OPS-14 has never
had a caller for, and — in the same pass — fix the stale verdict that shipping that trigger
alone would create.

Purpose: an operator correctly blocked from deploying by a critical finding has no
console-side way to clear the block. Adding the button without changing where the gate reads
its state produces something worse than no button: a control that appears to work, removes
the finding, and leaves the gate shut forever.

Output: the Adversary region as a component, and a page whose deploy-gate input comes from
what is open now rather than what was true when a run finished.
</objective>

**Binding records:** `23-01-PLAN.md § Open Decisions Resolved`. **OD-3** (the confirmation
styles are duplicated with a drift gate, not lifted), **OD-4** (the run row keeps three uses,
not one) and **OD-5** (the null-description fallback) all land in this plan.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| authenticated operator → contain route | A click permanently transitions a finding and, for a critical one, files a regression scenario into the golden suite. Its effect is not undone by clicking again. |
| open-findings list → the console's deploy-gate mirror | This list decides whether the room shows shut or open to the person deciding whether an agent may serve customers. |
| adversarial probe text → the operator's browser | Probe messages and agent responses are attacker-authored strings written to defeat a model, rendered into a privileged console. |
