  <action>
    A client component taking the agent identifier, an enabled flag and the region-error
    callback defined in 23-05. **This component owns its wiring into that callback**; the seam
    crosses two waves, so assert the call rather than assuming it.

    **The version list.** One query against the versions path. The service already orders
    newest first, so do not re-sort — a client-side sort that agrees with the server today is
    a client-side sort that disagrees with it after a server change nobody thinks to check.
    Render the ledger with four columns per the design contract: the version number, the label
    or a dash when it is null, the canary share, and the creation date. Ledger primitive, real
    caption, scope-correct headers, inside the existing horizontal scroll wrapper.

    The canary share goes through the shared renderer built in 23-03: absent and zero both
    render as zero per cent. A version routing no traffic is routing zero per cent of traffic;
    that is a measurement, not a gap, and rendering it as an absence would be the same mistake
    as WIRE-02 in a different column.

    With no versions at all, the locked empty state with its heading, body, and link to the
    soul editor. This state should not occur in practice — a version is written on every save —
    but the region must not break if it does, and the copy points at the action that creates
    one.

    **The comparison.** A selection mechanism for the two sides, defaulting to comparing the
    newest version against the one before it, which is the comparison an operator wants
    almost every time and which costs no interaction to offer. One query against the diff
    path, enabled only when two distinct versions are chosen, passing them as the two named
    query parameters.

    Render the four field pairs as before-and-after in the existing code-block treatment: two
    columns, plain text, with each field marked changed or unchanged from the flag the service
    already computed. **Render unchanged fields too**, marked as unchanged rather than hidden —
    an operator comparing two versions needs to know a field did not move, and a comparison
    that shows only differences cannot distinguish "unchanged" from "not compared".

    Two of the four fields are lists. Render their entries as separate lines on each side.
    Joining a list into one string makes a single reordered entry look like a total rewrite,
    which is exactly the misreading a comparison exists to prevent.

    No diff-highlighting library, no character-level marking, no syntax colouring. The design
    contract is explicit and the reasoning holds: this is four structured fields, not free
    text, and the restraint is the house style.

    **The canary action.** A bounded numeric input for the share and an action per version.
    Bound the input to the same range the request schema enforces so an out-of-range value is
    impossible to submit rather than merely refused; the server bound stays the authority and
    the client bound stays a courtesy.

    Staged, using the shipped confirmation shape and this phase's locked copy with the share
    and the version number interpolated. It is staged because percent routing is chosen at
    turn dispatch, so a confirmed share routes real customer conversations to that version
    immediately — the same class of live-the-instant-you-click-it action as the containment in
    the previous plan and the capability toggle before that.

    **The rollback action.** An action per version, staged, with the locked question and
    labels. The clause stating that nothing is deleted is load-bearing copy and must appear
    character for character. The service creates a new version carrying the restored content
    and removes nothing, and an operator who believes otherwise will hesitate over a safe
    action at exactly the moment they most need it — which is a real cost of a wrong sentence,
    not a stylistic preference.

    Both actions invalidate the versions query on success, so the list, the labels and the
    shares refresh from the server. No optimistic mutation of the list: both routes return the
    resulting version and the server is the authority on labels, which it moves as a side
    effect of setting a canary.

    Per-version busy state keyed by identifier, never a shared flag, with the settle handler
    clearing exactly one key. Failures go through the shipped transient per-row note with its
    self-clearing timer; query failures go to the region-error callback. No toast, no local
    banner.

    Styling per OD-2: inline style objects on existing tokens, plus the page's ledger, scroll
    and confirmation classes. Define no class, add no spacing value, introduce no hue. Nothing
    in this region is a verdict, so nothing in it is coloured.
  </action>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| authenticated operator → canary route | A confirmed share routes real customer conversations to a chosen version at the next turn dispatch. There is no staging environment between the click and a customer. |
| authenticated operator → rollback route | A confirmed rollback changes what a live agent says on its very next turn. |
| stored prompt content → the operator's browser | Soul fields are operator-authored, but they are rendered back into a privileged console and one of them can carry anything a previous author typed. |
