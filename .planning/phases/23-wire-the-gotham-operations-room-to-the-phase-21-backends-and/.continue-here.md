# THE SIX UI FINDINGS (from an actual render, 1440px, populated)

Rendered with a throwaway Playwright harness against `next dev -p 3100`, with Phase 21 payloads mocked at the network layer — deliberately mixing a **real zero**, a **real sentinel**, and **populated** values to exercise the three-state law.

**What the render proved works** (do not "fix" these):
- The **stale-verdict fix is real**: loading shows `GATE OPEN`; with data it flips to **`GATE SHUT`** carrying the critical finding's text, derived from live `open_findings`.
- Escalation **`0.0%` renders as a number**, not "not tracked" — a real zero survives as a real zero.
- `FAITHFULNESS` renders **"No queries in this window yet."** — the sentinel stays distinct from a value.
- Born-in-production **7** / authored **35** on screen. Zero horizontal overflow at 1440.
- The hardcoded `not tracked yet` in Judgement's per-scenario rows is **honest** — the results endpoint genuinely returns no trace linkage (`page.tsx:143`). Leave it.

### UI-1 (high) — Adversary header contradicts its own body
Top-right of the ADVERSARY region reads **"no programme run yet"** while directly beneath it sit severity counts (1 critical / 1 high / 1 medium / 0 low), a three-row coverage table, and three findings with Contain buttons.
*Why it matters:* the same false-status class WIRE-03 existed to remove — it survived by living in a region header instead of an `EmptyState`, so `check-ops-room-wiring.mjs` does not catch it.
*Hint:* the header label is derived from a different source than the body (likely `latestRedTeamRun` vs the programme query). Derive both from one.

### UI-2 (high) — `File` is irrevocable, looks identical to reversible actions, has no confirmation
All three bench grade buttons render as equal-weight neutral buttons. `bench_service.py:378` refuses any transition away from `filed` and the route answers 409 — permanent, server-enforced.
*Why it matters:* `Contain`, also irreversible, correctly got the staged `.cap-confirm` treatment in 23-06. The bench did not.
*Hint:* staged confirm on `File` only; leave `Hold`/`Dismiss` immediate. Copy should say filing cannot be undone.

### UI-3 (high) — red used as chrome, not as a verdict, in Retrieval health
Every reading-ledger row carries a maroon hairline, and the context-window bar renders red at **7.1% utilisation** — a healthy value.
*Why it matters:* GOTHAM's one governing law is *colour is a verdict*. Nothing here has failed. This is the same category of dishonesty as a false verdict chip.
*Hint:* neutral engraved-rule token per `20-UI-SPEC.md §2.2`; bar stays bone unless it crosses a defined threshold.

### UI-4 (medium) — "1 documents"
Unpluralised count, top-right of RETRIEVAL HEALTH. Check the other regions' count labels for the same bug.

### UI-5 (medium) — "Agent · Serving since —"
An em-dash placeholder in the page header subtitle, on a deployed agent. Reads as broken data rather than absent data — the three-state law applies here too.

### UI-6 (high) — unguarded nested reads crash ALL SIX regions
`page.tsx:560` reads `res.scores.faithfulness.toFixed(2)`, and the run tiles read `run.aggregate_scores.faithfulness`, with no optional chaining. A payload missing either nested object produced **"This page couldn't load"** — the entire ops room, not just Judgement. Reproduced twice.
*Why it matters:* an in-progress eval run or any partial payload blanks Live, Retrieval health, Bench, Judgement, Adversary and Prompt together. Everything else in this phase degrades honestly; this path does not degrade at all.
*Hint:* guard the nested reads and fall back to the region's own honest state. Consider a per-region error boundary.

## How to reproduce the render (do not rediscover this)

Four things block it, and all four are solved:

1. **No PostgreSQL / no API server** — irrelevant. Playwright `page.route()` intercepts at the network layer.
2. **Clerk auth** — `/agents/[id]` gates every query on `isLoaded && !!isSignedIn && step1Done` (**12 sites**) and every `queryFn` throws `'Not authenticated'` when `getToken()` returns null (**17 sites**). `NEXT_PUBLIC_DEMO=true` only makes routes public via `proxy.ts`; it does **not** make the sub-routes demo-aware. Both layers must be relaxed temporarily.
3. **Route precedence** — a catch-all glob competing with specific globs is ambiguous in either registration order. Use **one** `page.route('**/api/v1/**')` handler switching on `pathname`.
4. **Port 3100** — had a stale dev server from 23-08 returning 500. Killing it also released ~1.2 GB of held `.next` files.

Payload shapes that will crash you if guessed:
- `EvalRunSummary` needs nested `aggregate_scores.{...}` — not flat
- `EvalScenarioResult` needs nested `scores.{...}` — not flat
- match `/prompt-versions/diff` **before** `/prompt-versions`
- match `/results` **before** `/eval-runs`

**Everything patched to achieve this was reverted.** `git status --short -- apps/admin/` is empty; zero `NEXT_PUBLIC_DEMO` or demo-token residue under `app/agents/[id]/`; harness deleted; both gates re-verified green afterwards. This does not reverse OD-6 — no auth short-circuit shipped.
