Close Gap A: put the assistant message's real identifier on the terminal `agent.response`
SSE event, so the customer widget has the value `POST /widget/agents/{id}/feedback`
requires. Without this, WIRE-05 has nothing to send and cannot ship a working control.

Purpose: the id already exists. `_persist_messages` generates it, inserts it, and throws
it away. The function that owns the emit has never been able to see it.

Output: a three-part change in `agent.py` and the eight test mock sites that change breaks.
</objective>

## Open Decisions Resolved

Phase 23 was planned with research, patterns, a checker-approved UI-SPEC, and a validation
contract, but **no CONTEXT.md** — matching how Phases 15 through 22 were planned here. The
planner therefore owned and closed the decisions below. Each records the evidence, not only
the choice. These bind every plan in this phase.

**OD-1 — The four unwired regions become sub-components under `agents/[id]/components/`;
Judgement stays inline.**
`23-RESEARCH.md § Recommended Project Structure` raises this as a recommendation and its own
Open Question 2 leaves it to the planner. Adopted. `page.tsx` is 663 lines today with four
regions stubbed; fully inlining Live's eight-cell grid, Retrieval health's three sub-blocks
and twelve-row ledger, the bench's two-pane listbox, the Adversary coverage table plus
contain flow, and the whole prompt-version panel projects the file past 1800 lines.
`AlertsBanner.tsx` is the shipped precedent for the extraction, including its
callback-up idiom (`onAlertsChange`, `AlertsBanner.tsx:59-62,96-98`), which the Adversary
panel reuses to lift its findings back to the page's gate computation. **Judgement is
excluded deliberately**: it is already wired and correct, and WIRE-02's fix is a type
declaration plus two tile bodies. Extracting working code to satisfy a symmetry nobody asked
for is the kind of churn this project's own restraint rejects.

**OD-2 — Sub-components style themselves with inline token references, exactly as
`AlertsBanner.tsx` does, not with new page-local CSS classes.**
`AlertsBanner.tsx:126-202` uses `style={{}}` objects referencing GOTHAM custom properties
plus the globally-defined `mono` class, and depends on no page-local rule. That is the
shipped convention for a region living in its own file. The page-local classes that already
exist in `page.tsx`'s `PAGE_CSS` (`.chans`, `.chan`, `.chan-name`, `.chan-read`,
`.chan-val`, `.chan-thr`, `.sev`, `.sev-cell`, `.sev-n`, `.critical`, `.scroll-x`,
`.foot-note`) cascade to children and **are** reused by the panels; what the panels must not
do is require new ones.

**OD-3 — The staged-confirm CSS is duplicated into `page.tsx`'s `PAGE_CSS`, not lifted to
`globals.css`.**
This one is load-bearing and no upstream document states it. `.cap-confirm`,
`.cap-confirm-q`, `.cap-confirm-actions` and the two descendant button rules exist **only**
in `deploy/page.tsx`'s `PAGE_CSS`, at lines 2970-2974 — verified by grep; `globals.css`
contains none of them. `23-UI-SPEC.md § Spacing Scale` says the phase reuses
"`.cap-confirm`-family spacing already shipped in `globals.css` and `deploy/page.tsx`'s
`PAGE_CSS`", which is true as written but hides the operational consequence: the operations
room does not have these rules, so a staged-confirm block rendered there would be unstyled.
Lifting them to `globals.css` would require editing `deploy/page.tsx` to remove the
duplicate, and `ROADMAP.md`'s Phase 23 entry states plainly that this phase "shares no file"
with Phase 22, whose only artefact was that file. Decision: **copy the five rules verbatim
into `page.tsx`'s `PAGE_CSS`** in 23-06 (the first plan that needs them), with a comment
naming `deploy/page.tsx` as the source of truth, and a drift gate asserting the two blocks
are textually identical. Duplication with an enforced equality check is safer here than a
refactor that reaches into a file this phase promised not to touch.

**OD-4 — `latestRedTeamRun` keeps three uses, not one.**
`23-UI-SPEC.md § 3.3` locks the stale-verdict fix and says `latestRedTeamRun` should retain
"exactly one remaining use: the last programme run timestamp." The source disagrees. It is
read at `page.tsx:318` (`gateStamp`'s fallback), `:519` (the section-head timestamp) and
`:524` (the conditional deciding whether the severity tiles, coverage block and critical
banner render at all). The first two are display facts about when something happened and
stay. The third is the one that must change: with severity and the gate now derived from
live open findings, the region must render on **programme data**, not on the existence of a
run row, or an agent whose findings are all contained would lose its coverage table. The
spec's intent (never a verdict input) is honoured exactly; its count was wrong.

**OD-5 — A finding with a null description falls back to the sentence the page already
locks, not to a new string and not to an empty banner.**
`gateMessage` (`page.tsx:319-323`) renders `criticalFinding.description` today, where
`description` is a non-null field on the per-run JSONB shape (`page.tsx:81`). Gap B's
`open_findings` types it `string | null` by construction, because `red_team_findings` has no
description column and the correlation can miss. `23-UI-SPEC.md § 5` locks no copy for that
case. Decision: fall back to the generic sentence already present and already approved at
`page.tsx:322` — "A blocking signal is open. Nothing new reaches a customer until it
clears." — and keep rendering the attack vector and turn count in the mono span regardless,
since those come from real columns and are never null-by-correlation. Inventing a new
apologetic string would add copy the checker never approved; rendering an empty banner for a
critical finding would be the worst outcome of the three.

**OD-6 — The render-level browser spec is not built this phase. A browserless pure-function
gate and a static wiring gate are, and they are the ones that would have caught the defects
this phase exists to close.**
`23-RESEARCH.md § Validation Architecture` recommends `page.route()` fixture interception in
a new Playwright spec, and rates that recommendation MEDIUM confidence — its own words, "a
design judgment call, not a verified fact." Executing it requires two things this planner
