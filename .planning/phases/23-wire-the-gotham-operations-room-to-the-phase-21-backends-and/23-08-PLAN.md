<objective>
Wire the last dark region. The failure-triage flywheel — list a failing trace, grade it,
watch it become a permanent regression scenario — has a complete and correct backend and no
way in from the product. This gives it one.

Purpose: success criterion 2 of this phase is that the flywheel is reachable end to end from
the console. The backend chain from listing through grading through promotion to the ledger
count is already right and must not be touched; the only missing link is the operator's.

Output: the bench as a two-pane roving listbox with three grades, and its mount.
</objective>

**Binding records:** `23-01-PLAN.md § Open Decisions Resolved`. This region contains one of
the two items the pattern map flags as having **no analog anywhere in this codebase** — the
roving-listbox keyboard interaction. It is designed here explicitly against a written
contract rather than copied, and the fetch half is the house pattern as usual.

    **The two panes.** A contact sheet on the left and an enlarger on the right, using the
    layout classes Task 2 adds to the page's style block. Those classes are new: the two-pane
    shell Phase 20's spec described was never built, because Phase 20 shipped this region as an
    empty state — verified, there is no such rule in the shared stylesheet, and the similarly

    two-column collapse cannot be expressed as an inline style object, which is the one
    justified exception to OD-2 in this phase, and Task 2 owns it.

    **The sheet is a roving listbox, built to the contract and not improvised.** The container
    carries the listbox role and an accessible name. Each trace is a real button carrying the
    option role, its selected state, and a roving tab index — zero for the selected one and
    minus one for the rest — so a single tab stop enters the list and the arrow keys move
    within it. Moving the selection also moves focus to the newly selected option; without
    that the selected state and the focus ring drift apart and a keyboard operator loses their
    place. Arrow down and up wrap or clamp consistently, and Home and End jump to the ends.
    Handle the keys on the container so the events bubbling from the options are caught once.

    Each option row shows the first line of the customer's turn, the judge's verdict as a
    chip, and — only when the trace has been graded — a neutral badge naming the grade. The
    grade badge is never a pass or a fail. A grade is an operator's decision and rendering it
    with a machine verdict's colour asserts a judgement no machine made, which is the same
    rule Phase 22 locked and the same rule that made a merely-approved confirmation render
    neutral. Use the shared mapping from 23-03, which returns a neutral verdict by
    construction.

    **The enlarger** shows the selected trace in full: the customer's turn, the agent's turn,
    and the judge's reasoning in the judge-voice treatment. That treatment is used here and
    nowhere else in this phase; it is the one place a machine's own verdict prose is being
    quoted. Let long text wrap rather than truncate. A judge's reasoning or an adversarial
    transcript silently cut off is real information loss in a review surface, and the operator
    has no way to know something was removed.

    Below it, three actions: file, hold and dismiss, as ghost buttons with the labels the
    design contract fixes.

    **Filing is irrevocable and the grade actions are deliberately not staged.** That is the
    approved contract's decision — `23-UI-SPEC.md § 4.3` gives the three grades as plain
    actions and its considerations table lists this region's irrevocability as covered by the
    conflict response, the inert state and the locked caption, while listing only the
    containment, the canary and the rollback as staged. Do not add a confirmation here; a
    planner does not redesign an approved contract. Once a trace is filed, all three actions
    render inert with the locked caption stating that it has been filed and cannot be
    re-graded.

    **The grade shortcuts, and the safety rules they need.** The three keys act on the
    selected trace from anywhere within the region, per the contract. The contract does not
    state the guards, and a single keystroke that irrevocably files a trace and dispatches a
    permanent regression scenario needs them. Ignore the key when any modifier is held, when
    the event target is an input, a text area, a select or an editable element, and when a
    confirmation is open anywhere in the region. Also ignore it when the selected trace is
    already filed, matching the inert buttons. None of this changes the contract; it is the
    difference between a shortcut and a hazard, and it is stated here because no upstream
    document states it.

    **The announcement.** One visually-hidden polite live region using the shared class,
    receiving a sentence after each resolved grade naming the trace and the grade applied.
    This is required by the contract and is load-bearing rather than decorative: it is the
    only feedback a keyboard operator who used a shortcut receives.

    **The tally comes from the response.** The listing carries one and the grade response
    returns the updated one. Render the returned value; never increment locally. The promotion
    that filing dispatches is explicitly best-effort — the route logs a dispatch failure and
    still returns success, because the grade itself succeeded — so a locally incremented count
    would be the console asserting a suite state it cannot know. The grade is what this UI
    owns; the promotion is a backend concern by that code's own design.

    **The conflict.** A conflict response is the expected outcome of two operators grading the
    same trace, not an error. Throw with the trace identifier attached, catch it in the error
    handler, refetch, and show the locked note on that row through the shipped transient-note
    mechanism with its self-clearing timer and its cleanup effect. No toast, no error surface,
    no modal. Query failures go to the region-error callback.

    Per-trace busy state keyed by identifier with the settle handler clearing exactly one key.
    Grading one trace must never disable another's actions.

    **Empty.** The locked empty state, whose wording is deliberately more confident than the
    placeholder it replaces: with real data behind it, a clean bench is a genuinely good state
    rather than a promise about the future.

    Change nothing under the API. The listing, the grade, the promotion and the ledger count
    are correct and the roadmap forbids modifying that chain.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| authenticated operator → grade route | Filing a trace is irrevocable by design and permanently adds a scenario to the golden suite that every future eval run is measured against. |
| customer conversation content → the operator's console | Failing traces carry the customer's own words and the agent's reply to them, rendered in full in the enlarger. |
| keyboard event → an irrevocable action | A single keystroke files a trace. The keystroke arrives from anywhere within the region. |
