<objective>
Rewire the dispatcher to the atomic reserve-before-execute order, completing CR-02 and WR-01 end-to-end, and bind WR-02/IN-03 at the dispatcher boundary. Add the WR-05 capability gate + minimal dedup to confirm_action.

This is the integration plan: it adopts the reservation engine (14-06) and the enforcement split (14-07). After it lands, the legacy `check_idempotency`/`store_idempotency` calls and the legacy single `check_capability_envelope` call in the dispatcher are gone (the facades may remain for other callers but the dispatcher no longer uses them).

New dispatcher order in `_execute_transactional_tool`:
1. Precondition (IN-03): if agent_id is empty/unset -> return a clear is_error precondition message; do not touch the DB.
2. Authorization (every call, fail-closed, no side effects): `snapshot, denial = await check_capability_access(agent_id, skill)`. On denial -> write audit row (AUD-01 symmetry, error="capability.denial:<reason>") + is_error. This preserves the locked CONTEXT order ("capability check first" / a disabled skill is denied even on replay).
3. Reserve (idempotency, atomic): compute args_hash via compute_args_hash(raw_args); `res = await reserve_idempotency(agent_id, skill, validated.idempotency_key, args_hash)`.
   - res.state == "replay" -> log idempotency_replay + return res.result (NO rate-limit INCR — WR-01).
   - res.state == "args_mismatch" -> return is_error "idempotency key reused with different arguments" (WR-02). No release (genuine conflict).
   - res.state == "in_progress" -> return is_error/benign "this request is already being processed" (concurrent double-delivery; adapter NOT called).
   - res.state == "reserved" -> proceed (fresh winner).
4. Rate/constraint (fresh winner only, side-effecting): `denial = await apply_rate_and_constraint_checks(agent_id, skill, snapshot, validated)`. On denial -> `await release_idempotency(...)` (free the key for a later in-budget retry) + write audit row + is_error.
5. Actor seam: `decision, rationale = await call_actor_gate(...)`. On "block" -> release_idempotency + write audit (actor_decision="block", error="actor_block") + is_error.
6. Adapter execute (try/except, capture latency_ms + error). On exception -> release_idempotency + write audit (error=str) + is_error.
7. Success -> `await finalize_idempotency(agent_id, skill, key, tool_response)` + write audit (success) + return tool_response.

Purpose: close the BLOCKER and the highest-severity warnings at the call site; make UAT item 2 (live-DB durable replay) pass.
Output: rewritten dispatcher + gated confirm_action, extended unit tests, and a live-Postgres end-to-end replay test.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| LLM tool call -> dispatcher | untrusted skill/args/idempotency_key cross into the mutation path |
| Concurrent workers -> dispatcher -> control DB | acks_late redelivery; exactly-once must hold at the call site |
| LLM -> confirm_action -> pending_confirmations | unbounded row writes possible without a gate |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-14-08-01 | Elevation/Tampering | double-execution at the dispatcher | mitigate | reserve_idempotency before actor+adapter; adapter runs once; loser sees in_progress/replay (e2e + concurrency tests prove it) |
| T-14-08-02 | Tampering | replay consuming rate budget / returning rate_limit denial | mitigate | replay branch returns cached result before apply_rate_and_constraint_checks (WR-01) |
| T-14-08-03 | Spoofing/Tampering | idempotency key reused with different args returns wrong result | mitigate | args_mismatch -> explicit is_error, no replay, no execute (WR-02) |
| T-14-08-04 | Denial of Service | reservation orphaned on denial/block/error blocks retries | mitigate | release_idempotency on every pre-finalize failure path |
| T-14-08-05 | Denial of Service | unbounded pending_confirmations rows | mitigate | capability gate + minimal per-(agent,skill,action_reference)/per-turn dedup on confirm_action (WR-05) |
| T-14-08-06 | Tampering | invalid-UUID insert from unset agent_id | mitigate | IN-03 precondition guard returns is_error before any DB write |
| T-14-08-07 | Repudiation | missing audit row on a failure path | mitigate | AUD-01 audit row written on capability denial, rate/constraint denial, actor block, adapter error, and success |
| T-14-08-SC | Tampering | package installs | accept | no new packages |
</threat_model>
