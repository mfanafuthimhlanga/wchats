<objective>
Add the database substrate that makes an *atomic reserve-before-execute* idempotency guard possible (the BLOCKER CR-02 fix in 14-06/14-08 depends on it) and that lets an idempotency key be bound to its arguments (WR-02).

Today `tool_idempotency_keys` has `result JSONB NOT NULL` and no notion of a "reserved but not-yet-completed" row, so the guard can only be implemented as the broken check -> execute -> store sequence. This plan adds three columns and relaxes one constraint so a row can be INSERTed *before* the adapter runs and UPDATEd *after* it succeeds.

Purpose: unblock the atomic idempotency engine (14-06) and the dispatcher rewrite (14-08).
Output: migration `0015_idempotency_reservation.py`, an updated `ToolIdempotencyKey` ORM model, and `test_migration_0015.py`.

This plan does NOT change idempotency.py, enforcement.py, or tools.py — only the schema + model + a migration test. Every existing test stays green because the new columns have safe defaults (status defaults to 'completed' for any pre-existing rows; new code writes 'pending' explicitly) and `result` only loosens from NOT NULL to NULL.
</objective>

<artifacts_this_phase_produces>
NEW columns on `tool_idempotency_keys` (control DB):
- `status TEXT NOT NULL DEFAULT 'completed'` — reservation lifecycle: a row INSERTed by the new reserve path is written as `'pending'`; finalize flips it to `'completed'`. The column DEFAULT is `'completed'` so any row created by the legacy `store_idempotency` path (still live until 14-08) and any pre-existing row are treated as finished, never as an in-progress reservation.
- `args_hash TEXT NULL` — sha256 hex of the canonicalized tool arguments that created the row (WR-02). Nullable so legacy `store_idempotency` rows (which do not compute a hash) remain valid.
- `reserved_at TIMESTAMPTZ NOT NULL DEFAULT now()` — when the reservation was claimed; used by 14-06 to reclaim a stale `'pending'` row left behind by a crash so the key cannot deadlock forever.

CHANGED:
- `tool_idempotency_keys.result` — `JSONB NOT NULL` becomes `JSONB NULL` (a pending reservation has no result yet).

NEW migration: `0015_idempotency_reservation.py` (revision `0015`, down_revision `0014`).
NEW test file: `tests/unit/test_migration_0015.py`.
