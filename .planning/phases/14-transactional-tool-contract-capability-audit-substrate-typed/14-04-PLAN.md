<objective>
Wire the L1 contract to a real execution path: the 6 mutating tool handlers + `confirm_action_tool` in `transactional/tools.py`, composed through one shared `_execute_transactional_tool` dispatcher that encodes the enforcement order, then registered into the existing customer-agent tool loop (`build_tool_server`) with `allowed_tools` updated in `agent.py`.

This plan resolves the two open questions per planning guidance:
- (a) `confirm_action` is `mutating=False` — it writes a `pending_confirmations` row but executes no provider action, so it takes no idempotency key. Duplicate-confirmation dedup is deferred to Phase 18 (which resolves pending rows). This keeps the PRD §4.3 `pending_confirmations` DDL unchanged.
- (b) The idempotency LOOKUP is hoisted to run immediately after the capability check, so a replay (hit) short-circuits to the stored result BEFORE the Actor seam and adapter — avoiding a redundant Haiku call (latency/cost) on replays that execute nothing. Both security invariants still hold: the capability check runs first on every call (fail-closed even for replays), and `call_actor_gate` still gates 100% of actual (non-replay) executions. This is a deliberate, documented refinement of CONTEXT's literal "capability → Actor → idempotency" ordering.

Purpose: After this plan the full path (envelope → idempotency → actor seam → execute(stub) → audit) is exercisable end-to-end offline.
Output: `transactional/tools.py`, extended `agent_tools.py` + `agent.py`, the phase's main behavior test.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Claude tool dispatch → mutating tool handler | The single code path to a provider mutation; the enforcement stack here is the last line before a real side effect (Phase 16) |
| actor seam call site | The ONLY pre-execution hook for mutating tools; if a handler skipped it, Phase 15's gate would be defeated |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-14-04-01 | Elevation of Privilege | bypassed Actor seam | mitigate | call_actor_gate is awaited inside the single shared dispatcher before the adapter on every fresh mutating execution; a block writes an audit row and returns is_error |
| T-14-04-02 | Repudiation | replay double-execute | mitigate | idempotency lookup short-circuits replays to the stored result before the adapter; store_idempotency (ON CONFLICT) after success |
| T-14-04-03 | Tampering | capability bypass via allowed_tools listing | mitigate | allowed_tools only suppresses SDK permission prompts; the fail-closed envelope check in the handler is the real gate |
| T-14-04-04 | Information Disclosure | cross-tenant audit/confirmation rows | mitigate | agent_id sourced from the per-call ContextVar; all control-DB writes scoped to that agent_id |
| T-14-04-05 | Repudiation | confirm_action duplicate rows | accept | mutating=False, no idempotency key; duplicate-confirm dedup deferred to Phase 18 (resolves pending rows); PRD DDL unchanged |
| T-14-04-SC | Tampering | dependency supply chain | accept | No new packages — claude_agent_sdk already pinned and in use |
</threat_model>
