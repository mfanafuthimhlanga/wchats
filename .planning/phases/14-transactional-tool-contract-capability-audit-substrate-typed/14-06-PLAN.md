<objective>
Replace the broken non-atomic idempotency guard with an atomic reserve-before-execute engine. This is the core of the CR-02 BLOCKER fix and folds in WR-02 (argument binding) and the WR-03 executor-offload for this module's blocking DB calls.

The dispatcher rewrite in 14-08 consumes the new API; this plan only builds and tests the engine. To keep every commit green, the existing `check_idempotency` / `store_idempotency` functions are RETAINED unchanged as facades — the unchanged 14-04 dispatcher and `test_tool_idempotency.py` keep working until 14-08 switches over.

New API:
- `compute_args_hash(args: dict) -> str` — sha256 hex over canonical JSON (sorted keys, idempotency_key excluded so the same logical call hashes stably) of the tool arguments.
- `reserve_idempotency(agent_id, skill, key, args_hash) -> Reservation` — atomic claim. Returns a small result object/dataclass describing one of: `reserved` (winner, fresh), `replay` (loser, completed -> carries the stored result), `in_progress` (loser, still pending and not stale), `args_mismatch` (loser whose stored args_hash differs).
- `finalize_idempotency(agent_id, skill, key, result) -> None` — UPDATE the pending row to status='completed', result=:r.
- `release_idempotency(agent_id, skill, key) -> None` — DELETE the row only while status='pending' (never delete a completed row).

Purpose: make "exactly one execution per key" a DB-enforced invariant under acks_late concurrent redelivery + crashes.
Output: rewritten idempotency.py (additive), extended unit tests, and a new live-Postgres concurrency test.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Concurrent Celery workers -> control DB | acks_late redelivery can run the same logical tool call twice; the DB reservation is the arbiter |
| LLM-supplied idempotency_key + args -> reservation | the model controls the key; arguments must be bound to it |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-14-06-01 | Elevation/Tampering | double-execution of a mutation under concurrent redelivery | mitigate | atomic INSERT ... ON CONFLICT DO NOTHING RETURNING reserves before execute; loser gets in_progress/replay, never executes (proven by integration test) |
| T-14-06-02 | Tampering | key reused with different args returns wrong result | mitigate | args_hash bound at reserve; args_mismatch state surfaces an error, not a stale replay (WR-02) |
| T-14-06-03 | Denial of Service | orphaned pending row deadlocks a key after a crash | mitigate | reserved_at lease + reclaim path re-acquires a stale pending reservation |
| T-14-06-04 | Information Disclosure | idempotency keys leaking to Redis | mitigate | control-DB only; module imports no redis (TestNoRedisUsage retained) |
| T-14-06-SC | Tampering | package installs | accept | no new packages (stdlib hashlib/json/asyncio + existing sqlalchemy) |
