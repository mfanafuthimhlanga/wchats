## Element-by-element diff

### 1. Left sidebar — BACKGROUND IS WRONG
- Reference: **no background at all** — sidebar has zero background color, skyline shows through the sidebar exactly as it does through the rest of the page. Only a vertical right border (`1px solid var(--glass-border)`) separates it.
- Current: `background: var(--glass-bg-strong)` = `rgba(40,28,72,0.70)` — renders as a solid dark-purple rectangle obscuring the skyline behind the sidebar.
- **Fix: Remove `background`, `backdropFilter`, `WebkitBackdropFilter` from JourneyStepper `<aside>` in `apps/admin/app/components/JourneyStepper.tsx`.**

### 2. Left sidebar — AGENT NAME FONT
- Reference: Agent name "New agent" uses `font-family: var(--font-display)` (Fraunces), `font-weight: 700`, `font-size: 16px`.
- Current: Agent name uses `fontWeight: 700, fontSize: '18px'` — no Fraunces. Wrong size.
- **Fix: Add `fontFamily: 'var(--font-display)', fontVariationSettings: '"opsz" 144, "SOFT" 30', fontSize: '16px'` to the agent name h2 in JourneyStepper.**

### 3. Right panel — INPUT FIELD COUNT IS WRONG
- Reference: **3 fields**: Agent name, Primary role, Business domain.
- Current: **2 fields**: Agent name, Role (a `<select>`).
- The "Primary role" in reference is a **text input** with placeholder "e.g. Customer service agent for Acme Consulting" and hint "Used as the role context in the system prompt. Be specific."
- The "Business domain" is a text input with placeholder "e.g. SaaS company, property agency, e-commerce".
- **Fix: Add a `primaryRole` text state, add a `businessDomain` text state. Replace the `<select>` with a text input for Primary role. Add Business domain field. The existing `role` state (support/sales/helpdesk) can default to 'support' for the API call — the primary role text is the human-facing description that feeds the system prompt.**

### 4. Right panel — INPUT FIELD BORDER RADIUS
- Reference: inputs use `border-radius: var(--radius-sm)` = 14px — noticeably pill-like.
- Current: inputs use `border-radius: var(--radius-xs)` = 8px — squarer.
- **Fix: In `inputStyle`, change `borderRadius` from `var(--radius-xs)` to `var(--radius-sm)`.**

### 5. Right panel — INPUT FIELD PADDING
- Reference: `padding: 11px 14px`.
- Current: `padding: '10px 12px'`.
- **Fix: Update inputStyle padding to `'11px 14px'`.**

### 6. Right panel — INPUT TEXT COLOR (readability)
- Reference: Input text color is `var(--text-1)` = `#F4EDE5` — clearly legible light cream.
- Reference: Placeholder text is `var(--text-4)` — muted.
- Current: inputStyle sets `color: 'var(--text-1)'` — token is correct, but the value in globals.css must be verified. The screenshot shows inputs that are hard to distinguish from the background.
- **Fix: Verify `--text-1` in `apps/admin/app/globals.css` is `#F4EDE5`. If not, correct it. Also check `--surface-2` is `#2A1E4A` — the reference uses this for input backgrounds, which is meaningfully lighter than the dark page overlay.**

### 7. Right panel — FORM CONTAINER MAX-WIDTH
- Reference: The form fields fill the right content area fully (no maxWidth constraint visible — the 3 inputs span the available width).
- Current: Form has `maxWidth: '560px'` which constrains the fields when the viewport is wider.
- **Fix: Remove or increase the `maxWidth` on the form element in `/agents/new/page.tsx`. The reference has no maxWidth on the form — the right content area (`flex: 1, padding: 40px 48px`) is the natural constraint.**

### 8. Panel footer — STEP COUNT / CONTINUE BUTTON (verify after fix)
- Reference footer: left spacer | "Step 1 of 4" center | "Continue →" right, with `border-top: 1px solid var(--border-soft)`.
- The continue button should fire the mutation (create agent) on click, not be a type="submit" that triggers form validation on empty fields in an unexpected way.
- **Verify: After the above fixes, screenshot and confirm footer layout matches reference.**
