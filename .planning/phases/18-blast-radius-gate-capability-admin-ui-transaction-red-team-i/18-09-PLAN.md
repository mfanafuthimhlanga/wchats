<objective>
Split the shipped M7 prompt-injection red-team agent into two variants: conversation injection (the
attacker is in the chat) and content injection (the attacker is in an ingested document and is not
present when the attack lands).

Purpose: these are two different threats with the same symptom. `sanitize_chunk_text` strips markers at
admit time and plan 18-02's `_frame_retrieved_context` frames chunks at retrieval time, but neither is
proven by a probe that only ever speaks in the chat window. The content-injection variant is what tests
whether the retrieval-time framing actually holds when a poisoned chunk is already in the corpus.

Output: the renamed conversation runner plus a backward-compatible alias, a new content-injection runner
and its poisoned-chunk seeder, the two sequential calls in `run_red_team`, and the pinned test case.

**Decisions:** see `18-01-PLAN.md` § Open Decisions Resolved — this plan implements **OD-7** (rename plus
alias, two `attack_vector` values, no schema change, direct chunk seeding with a fixed vector rather than
running the real ingestion pipeline).

**Wave placement is deliberate.** This plan modifies `red_team_service.py` and
`worker/tasks/runtime/red_team.py`, the same two files plan 18-06 modifies in wave 2. Two plans must not
contend for one file in the same wave, so this one runs in wave 3 and depends on 18-06. Its unit tests
live in `tests/unit/test_red_team_service.py`, which plan 18-06 deliberately left untouched (18-06 wrote a
separate `test_red_team_rtx_runners.py` for exactly this reason).
</objective>

## Verified facts about the code this plan touches

- `run_prompt_injection_agent` (`red_team_service.py:214-304`) is the runner to rename. Its four attack
  sequences are described in prose inside its `system_prompt` (direct instruction override, role-play
  hijack, hypothetical framing, system-prompt extraction), all delivered via `send_probe` chat messages —
  i.e. attacker-in-the-chat. Behaviour is unchanged by the rename.
- The runner contract is `(probe_fn: Callable[[str], str], max_turns: int, attack_sequences: int) -> list[RedTeamFinding]`
  and every runner ends with the same
  `asyncio.run(asyncio.wait_for(_run_agent_loop(...), timeout=120.0))` inside a `try/except Exception`
  that logs `red_team_agent.failed` and returns `[]`.
- `classify_severity` (line 73) is reused unchanged.
- `red_team_strategies.attack_vector` is free `TEXT` with only a `UNIQUE` constraint and no CHECK or enum
  (`alembic_tenant/versions/0012_red_team_programme.py`), and `run_red_team` Step 7b already upserts with
  `INSERT INTO red_team_strategies (attack_vector, description) VALUES (%s, %s) ON CONFLICT (attack_vector) DO NOTHING`
  (`red_team.py:390-404`). **Two new distinct `attack_vector` strings therefore become two separate
  strategy rows with zero migration work.**
- Step 7c writes one `red_team_findings` row per finding with `status='open'`, so a content-injection
  critical inherits Phase 21's live deploy-gate behaviour with no extra wiring.
- After plan 18-06, `run_red_team` Step 5 calls **six** runners sequentially; after this plan it calls
  **seven** (the single prompt-injection call becomes two).
- The tenant `chunks` table is written by the ingestion pipeline after `sanitize_chunk_text`. The eval
  fixture precedent for a hand-seeded chunk is `demo_business_tenant.sql`, which uses a **zero
  `vector(1024)`** rather than a real embedding, recorded as a Phase 4 decision.
- BM25 retrieval is native `tsvector` + `ts_rank_cd` (CLAUDE.md rule 8), so a seeded chunk with a zero
  vector is still findable through the lexical half of the hybrid retrieval.

generated `chunk_id`, `POISONED_CHUNK_TEXT` as its content, and a **zero vector** of
`POISONED_CHUNK_VECTOR_DIM` dimensions as its embedding, then commits and closes in a `finally`. It calls

red-team probe that must not depend on provider availability); and that the chunk is still retrievable via
the native `tsvector` BM25 half of hybrid retrieval (CLAUDE.md rule 8). Never log `conn_str`. Return the
chunk id.

its own `try/except Exception` logging a warning rather than raising, so a cleanup failure cannot fail a
red-team run. A probe that leaves a poisoned chunk in a tenant's live corpus would be a self-inflicted
security defect, so cleanup must always be attempted.
