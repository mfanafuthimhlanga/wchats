<objective>
Close the two output-and-retrieval hardening requirements that are independent of the BLR/CAP
cluster: SEC-01's L4 synchronous PII output firewall, and SEC-02's L6 data-not-instructions framing
on retrieved context.

Purpose: Both are single-call-site changes on the live customer turn, and both must be synchronous.
The Gatekeeper/Auditor/Strategist validators run **asynchronously after the SSE response has already
streamed** (`app/worker/tasks/runtime/agent.py`, validator chord fires at the end of the task body),
so a PII leak cannot wait for a post-hoc judge — it has to be caught in the response path itself.

Output: a new `app/utils/pii_firewall.py` regex module, its one unconditional call site in the
`run_agent_turn` body, the `retrieve_tool` tool-result framing, and unit coverage for both.

**Decisions:** see `18-01-PLAN.md` § Open Decisions Resolved — this plan implements **OD-4**
(redact-and-deflect, three structurally-validated detectors, no phone-number regex) and **OD-5**
(framing at `retrieve_tool`'s final return only, additive to `sanitize_chunk_text`).
</objective>

reads, no LLM call.

Public surface:
- `PII_DEFLECTION: str` — the generic deflection text served in place of a flagged response. Exact
  value: `"I can't share that here. For anything involving personal or payment details, please contact our team directly and we'll help you securely."` Sentence case, no em dash, no emoji (DESIGN.md voice rules).
- `detect_pii(text: str) -> str | None` — returns a short detector name (`"email"`, `"card"`,
  `"sa_id"`) on the first match, or `None`. Fail-open on empty/None input by returning `None`.
- `scan_response(text: str) -> tuple[str, str | None]` — returns `(PII_DEFLECTION, detector_name)`
  when `detect_pii` matches, else `(text, None)`. The original text is returned **byte-identical**
  when clean — no strip, no normalisation.

Detectors (OD-4 — exactly three, all structurally validated so a legitimate business answer does not
trip them):
- `_EMAIL_RE` — a compiled pattern for `local@domain.tld` with a 2+ char TLD, `re.IGNORECASE`.
- `_CARD_RE` — a compiled pattern for a 13-19 digit run allowing single spaces or hyphens as group
  separators, anchored on word boundaries. A regex match is **not sufficient**: strip separators and
  require `_luhn_ok(digits)` before reporting `"card"`. This is what keeps order numbers, invoice
  references and long product SKUs from being flagged.
- `_SA_ID_RE` — a compiled pattern for exactly 13 consecutive digits on word boundaries. A match is
  **not sufficient**: require that the first six digits parse as a plausible `YYMMDD` (month 01-12,
  day 01-31) **and** that `_luhn_ok` passes on all 13 digits (South African ID numbers carry a Luhn
  check digit). Only then report `"sa_id"`.
- `_luhn_ok(digits: str) -> bool` — standard Luhn: right-to-left, double every second digit,
  subtract 9 when the doubled value exceeds 9, sum, and require `total % 10 == 0`. Return `False` for
  any non-digit input rather than raising.

Deliberately **not** implemented: any phone-number detector. Record the reason in the module
docstring in terms of the false-positive class it avoids (a tenant's own published support line is
content the agent is supposed to hand out, and flagging it turns a helpful answer into a deflection —
RESEARCH Pitfall 3).

The module docstring must also record: that this is the L4 output firewall, that it is applied
synchronously in the response path because the Gatekeeper/Auditor/Strategist validators run async
after the response has already streamed, that PRD v1.1 scopes it to regex only with the schema-bound
and Claude-classifier passes deferred to v1.2, and that the function takes no flag and reads no
config so nothing in the response text or the agent soul can switch it off.
