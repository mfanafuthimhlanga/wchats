<objective>
Expose the OTP flow over HTTP and wire the verified session token into the agent-turn dispatch.
Two new widget routes — `POST /widget/{agent_id}/identity/request` (issue a code, 204) and
`POST /widget/{agent_id}/identity/verify` (exchange a correct code for a session token, 200) — reuse
the existing widget JWT validation, Redis rate-limit, and CORS patterns. The chat route is extended
to carry `verified_session_token` from `WidgetChatRequest` into `run_agent_turn.apply_async` as the
5th arg, completing the transport rail begun in 17-03.

Purpose: IDV-02 (email) + IDV-03 (SMS) HTTP surface, and the IDV-05 client to server token transport.
Output: Otp schemas + `verified_session_token` field; two identity routes; the chat-route 5th arg;
`test_identity_routes.py`.

Enumeration mitigation (locked): the request route ALWAYS returns 204 regardless of whether the
external_id is known; verify returns the SAME 4xx for "expired" and "wrong code" so the endpoint is
not an oracle. The token is NEVER logged (T-04-03-05 parity with `message`).
</objective>

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-17-18 | Denial of Service | identity/request (SMS flooding/cost) | mitigate | Per-IP 10/min (route) + per-external_id send cap (service) + widget JWT required on both routes |
| T-17-19 | Information Disclosure | enumeration / error oracle | mitigate | Request always returns 204; verify returns identical 400 for expired vs wrong code |
| T-17-11 | Information Disclosure | token/code in logs | mitigate | otp_code and verified_session_token omitted from every structlog line |
| T-17-07 | Elevation of Privilege | session fixation | mitigate | Token minted server-side by verify_otp; the client never supplies its own token to the verify route |
| T-17-20 | Spoofing | JWT bypass on identity routes | mitigate | `validate_widget_jwt` runs first on both routes (agent_id claim must match the path) |
</threat_model>
