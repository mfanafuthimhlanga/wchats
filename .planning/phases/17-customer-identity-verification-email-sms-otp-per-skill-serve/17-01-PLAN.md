<objective>
Establish the Phase 17 foundation: the `customer_identities` tenant-DB table (IDV-01) and the
global OTP/session settings that every later plan reads. Apply the migration to a live local
Postgres tenant DB and prove the table + indexes + UNIQUE constraint exist — a migration file
alone does not satisfy IDV-01; the table must exist in the live DB.

Purpose: Everything in Phase 17 (OTP verify UPSERT, verified-session lookup, TTL config) depends
on this table and these settings existing first.
Output: `0008_customer_identities.py` migration, `config.py` M17 settings block, and a live
migration-roundtrip integration test.

Planner-locked Open Design Decisions (no CONTEXT.md — recorded here for user review):
- OD-1 (scope): `customer_identities` is PER-TENANT — NO `agent_id` column. UNIQUE(external_id).
- OD-3 (OTP state): OTP challenge state lives in Redis (TTL), NOT a DB table — so this migration
  creates ONLY the durable verified-session record, not an `otp_pending` table.
- OD-4 (session TTL): global `VERIFIED_SESSION_TTL_SECONDS = 3600` for Phase 17 (per-envelope TTL
  deferred to Phase 18).
</objective>
