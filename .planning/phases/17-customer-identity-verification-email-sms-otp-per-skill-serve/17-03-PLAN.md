<objective>
Build the IDV-05 enforcement plumbing: a task-scoped `_verified_session_token_var` ContextVar and
the threading that carries a customer's verified session token from the Celery task into that
ContextVar, so the transactional dispatcher (17-06) can read it deterministically. This plan adds
NO enforcement logic yet — only the transport rail. Both new parameters default to empty string, so
this change is fully backward compatible and can land in Wave 1 independently.

Purpose: Decouple the plumbing (ContextVar + task signature) from both the OTP service (17-04) and
the enforcement gate (17-06), maximizing parallelism and keeping each concern reviewable.
Output: `_verified_session_token_var` in agent_tools.py; `build_tool_server(..., verified_session_token="")`;
`run_agent_turn(..., verified_session_token="")` forwarding the token.

Constraint (CLAUDE.md rule / T-04-03-05): the verified_session_token is NOT a connection string and
MAY be a Celery task arg, but it MUST NEVER be logged — treat it exactly like `message`.
</objective>
