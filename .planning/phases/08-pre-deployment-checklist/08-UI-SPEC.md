## State Machine Contract

The Pre-Deploy tab renders one of five exclusive states based on `checklistState.kind` and `run.recommendation`.

```
ChecklistState:
  { kind: 'idle' }
    → renders: No Run State
  { kind: 'running'; runId: string }
    → renders: Running State (polls every 3s)
  { kind: 'complete'; run: ChecklistRun }
    → if run.recommendation === 'block'         → renders: Blocked State
    → if run.recommendation === 'ship_with_warnings' → renders: Ship With Warnings State
    → if run.recommendation === 'ship'          → renders: Ship State (no warnings, approve enabled)
  { kind: 'approved' }
    → renders: Approved/Deployed State
```

### State 1: No Run State

**Mockup reference:** State-switcher tab "1. No Run" in `08-predeploy-mockup.html`

Layout: centered empty-state card (border: `2px dashed var(--border)`, padding: `64px 40px`, text-align: center), matching eval/page.tsx empty state.

Elements:
- Heading (16px, weight 600, var(--text-1)): "Ready to deploy your agent?"
- Body copy (14px, var(--text-3), max-width 420px, centered): "Run the pre-deployment checklist to verify your agent meets quality standards before going live. The check takes 1–2 minutes."
- Primary CTA button: label "Run pre-deployment checklist", style: `background: var(--accent)`, `color: #fff`, `padding: 10px 18px`, `borderRadius: var(--radius-xs)`, `fontWeight: 600`, `fontSize: 14px`

On click: POST `/api/v1/agents/{id}/checklist-runs` → on 202 response, set `checklistState = { kind: 'running', runId: data.checklist_run_id }`.

Error handling: if POST fails, show inline alert with `var(--red-bg)` / `var(--red)` styling (matches deploy/page.tsx `loadError` pattern).

### State 2: Running State

**Mockup reference:** State-switcher tab "2. Running" in `08-predeploy-mockup.html`

Layout: same card container as State 1, centered.

Elements:
- Spinner: CSS `animation: spin-cw 1s linear infinite` (keyframe already in globals.css), 32px circle, border: `3px solid var(--border)`, `borderTopColor: var(--accent)`
- Heading (16px, weight 600, var(--text-1)): "Checking your agent's readiness…"
- Body (14px, var(--text-3)): "This usually takes 1–2 minutes. Your results will appear here automatically."

Polling: `setInterval(() => fetchRun(runId), 3000)` — cleared when `run.status === 'complete'` or `'failed'`. On `'failed'`: set `checklistState = { kind: 'idle' }` and show error alert.

## API Call Contract (Frontend)

All API calls use Clerk Bearer token from `useAuth().getToken()` — matching existing pages.

| Action | Method + URL | On Success | On Error |
|--------|-------------|------------|----------|
| Run checklist | `POST /api/v1/agents/{id}/checklist-runs` | Set state → running | Show red alert banner |
| Poll run status | `GET /api/v1/agents/{id}/checklist-runs/{runId}` | Update state on complete/failed | Log, continue polling |
| Acknowledge warning | `POST /api/v1/agents/{id}/checklist-runs/{runId}/acknowledge` | Update local acknowledged Set | Show inline error |
| Approve deployment | `POST /api/v1/agents/{id}/approve-deployment` | Set state → approved | Show red alert banner |

Poll interval: exactly 3000ms (`setInterval(..., 3000)`). Cleared on `status === 'complete'` or `status === 'failed'`.
