# Phase 10 — UI Design Contract

> Visual and interaction contract for Plan 10-04 only (AlertsBanner + Langfuse link).
> Plans 10-05 and 10-06 have zero UI surface and are out of scope for this spec.
> Generated by gsd-ui-researcher. Verified by gsd-ui-checker.

---

## Scope

This contract covers exactly two UI additions to the existing agent detail page
(`apps/admin/app/agents/[id]/page.tsx`):

1. `AlertsBanner.tsx` — new client component that polls for unresolved alerts and
   renders one row per alert with a Resolve action.
2. Langfuse link — a static external link to the Langfuse dashboard, placed in a
   footer strip at the bottom of the right-panel content area.

No existing component is replaced. No new npm packages are introduced.

### Alert row surface specification

**Warning alert row:**
- Background: `background: 'var(--amber-bg)'` (#FEF3C7)
- Border: `border: '1px solid rgba(146, 64, 14, 0.20)'` (amber 20% opacity)
- Badge: `bg-amber-100 text-amber-800` (Tailwind, maps to #FEF3C7 / #92400E)

**Critical alert row:**
- Background: `background: 'var(--red-bg)'` (#FEF2F2)

## Component Specification: AlertsBanner

### Mount location

AlertsBanner mounts **above the dispatch panel** (above the `{panel}` render call) in
the right-panel content area of `apps/admin/app/agents/[id]/page.tsx`. Specifically,
it is placed after the error alert div and before `{panel}`:

```
<div style={{ padding: '32px 40px' }}>
  {/* Error alert — existing */}
  {loadError && <div role="alert">…</div>}

  {/* AlertsBanner — NEW, mounts here */}
  <AlertsBanner agentId={id} />

  {/* Dispatch panel — existing */}
  {panel}
</div>
```

Rationale: Alerts are operationally urgent and must be seen regardless of which
journey stage panel is active. Placing them above the panel mirrors the existing
`loadError` alert pattern — critical information before content.

### Count badge

No separate count badge in a header or tab. The AlertsBanner itself is the indicator.
When alerts exist, the banner fills the space above the panel content; the visual
weight of one or more alert rows is sufficient signal. Adding a badge to the
JourneyStepper sidebar would require prop-drilling through layout.tsx and is
disproportionate to the phase scope.

### Auth pattern

AlertsBanner is a client component. It uses `getToken()` from `useAuth()` (Clerk)
to acquire a Bearer token, matching the fetch pattern used by the agent detail page,
deploy page, and eval page. There is no `apiKey` prop — the plan spec reference to
`apiKey` does not match the actual codebase auth pattern (all client components use
Clerk Bearer tokens, not X-API-Key headers).

```tsx
const { getToken } = useAuth()

const fetchAlerts = async () => {
  const token = await getToken()
  if (!token) return
  const res = await fetch(`${apiBase}/api/v1/agents/${agentId}/alerts`, {
    headers: { Authorization: `Bearer ${token}` },
  })
  if (res.ok) setAlerts(await res.json())
}
```

### Polling

- Interval: 30 000ms (30 seconds) via `setInterval` in `useEffect`.
- Cleanup: `clearInterval` on unmount.
- No loading spinner shown during polls — silent refresh. Initial load also silent.
- On network error: catch silently, retain previous state (no error UI from polling).

### Null render

When `alerts.length === 0`, the component returns `null`. No empty state, no
placeholder div, no collapsed accordion. The component takes up zero DOM space.

### Alert row layout

Each row uses a flex container with `items-start justify-between`:

- Left side: severity badge + alert_type label on one line; message body on the
  next line.
- Right side: Resolve button, vertically centered, shrink-0.

```
[CRITICAL] Eval Regression                    [Resolve]
Faithfulness score dropped below threshold.
```

### Severity badge

- Rendered as an inline `<span>` before the alert_type label.
- Text is uppercase (CSS `text-transform: uppercase` via Tailwind `uppercase` class).
- Font: 12px / weight 600.
- Padding: `px-1.5 py-0.5` (6px horizontal, 2px vertical).
- Border-radius: `rounded` (4px, matching `--radius-xs` nearest Tailwind equivalent).
- Colors: see Color section above.

### alert_type label display

| API value | Display string |
|-----------|---------------|
| `eval_regression` | Eval Regression |
| `red_team_critical` | Critical Red Team Finding |
| Any other value | Raw value with underscores replaced by spaces, title-cased |

### triggered_at formatting

Display as relative time: "2h ago", "5m ago", "just now" (< 60 seconds).
Rationale: Alerts are operational signals; owners ask "how recent is this?" not
"what was the exact ISO timestamp?". Relative time is more actionable.

Implementation: compute `Math.floor((Date.now() - new Date(triggered_at)) / 1000)`
and format with a local helper (no date library dependency):
- < 60s: "just now"
- < 3600s: "{n}m ago"
- < 86400s: "{n}h ago"
- >= 86400s: "{n}d ago"

The triggered_at text appears on the second line after the message, styled as
12px / weight 400 / `var(--text-3)`.

### Resolve button

Style: text link (no background, no border). NOT an outlined button or a filled
button. Rationale: The Resolve action is secondary — the primary purpose of the row
is to display the alert. A text link matches the "Resolve" affordance used in similar
operational UIs and avoids visual competition with the severity badge.

Exact style:
- Font size: 12px
- Color (default): `var(--text-3)` (#8A6060)
- Color (hover): `var(--text-1)` (#1A0A0F)
- Text decoration: underline
- No background, no border, no padding (only `ml-4 shrink-0` margin)
- Cursor: pointer

On click:
1. Optimistic update — immediately remove the resolved alert from local state
   (`setAlerts(prev => prev.filter(a => a.id !== alertId))`).
2. POST to `/api/v1/agents/{id}/alerts/{alertId}/resolve` with Bearer token header.
3. No error handling for the POST — if it fails, the next 30-second poll will
   restore the alert. No undo UI needed.
4. No confirmation dialog — Resolve is not destructive (it can be re-triggered by
   the backend if the condition persists).

### Animation on resolve

No animation. The row disappears immediately via React state update. No slide-out,
no fade, no transition. Rationale: the component has no CSS animation budget and
adding one requires `transition` classes not present in the existing codebase pattern.

## Component Specification: Langfuse Link

### Placement

The Langfuse link is placed at the **bottom of the right-panel content**, after the
dispatch panel (`{panel}`). It is always visible regardless of journey stage.

```
<div style={{ padding: '32px 40px' }}>
  {loadError && …}
  <AlertsBanner agentId={id} />
  {panel}

  {/* Langfuse link — always visible */}
  <div style={{ marginTop: '24px', paddingTop: '16px',
                borderTop: '1px solid var(--border-soft)' }}>
    <a
      href="https://cloud.langfuse.com"
      target="_blank"
      rel="noopener noreferrer"
      style={{ fontSize: '13px', color: 'var(--text-3)',
               textDecoration: 'underline' }}
    >
      View Langfuse Dashboard →
    </a>
  </div>
</div>
```

### Style

- Font: 13px / weight 400 / `var(--text-3)` (#8A6060)
- Hover: `var(--text-1)` (#1A0A0F), no underline change
- A thin `border-top: 1px solid var(--border-soft)` separates it from the panel
  above, providing visual separation without a heavy divider.
- `marginTop: '24px'` gap above the border-top, `paddingTop: '16px'` between border
  and link text.
- The trailing `→` is a literal Unicode character (U+2192), not an icon library glyph.

### href

Static string `https://cloud.langfuse.com`. Do not use `process.env.NEXT_PUBLIC_LANGFUSE_HOST` — that env var is not currently declared in the Next.js config and the static default is the correct production target for all users. If tenant-specific Langfuse routing is needed in a future milestone, it can be parameterized at that time.

### Target / rel

`target="_blank"` with `rel="noopener noreferrer"`. No confirmation dialog before
navigating externally.

## Interaction States

| State | What the User Sees |
|-------|--------------------|
| No alerts (initial load) | Nothing — component renders null |
| Alerts present | One or more alert rows above the panel |
| Resolving (optimistic) | Row disappears immediately on button click |
| Poll refresh | No visible change — silent background refetch |
| Auth not loaded | `fetchAlerts` returns early; no render until `isLoaded && isSignedIn` |
| Network error on poll | Silent — previous alert state retained until next poll |
