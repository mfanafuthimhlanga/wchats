<objective>
Make live agent turns reliably complete on the $0 Voyage free tier by capping
retrieves-per-turn (D-10), raising the wall-clock guard (D-11), and adding an
optional Redis query-embedding cache (D-13). These are the ONLY in-repo
production code changes in Phase 12 and the only ones carrying pytest unit tests.

Purpose: The live E2E test on 2026-05-29 failed because the agent issued 6
`retrieve` calls in one turn, blowing past Voyage's 3 RPM free tier, and the 30s
wall-clock guard was too tight for the Agent SDK warm-up on a slower ARM VM.
Output: Two surgical edits in `agent.py` (verified by two new unit tests), plus a
Redis cache for repeat queries in `agent_tools.py`.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| hiring-manager browser → widget JWT → /widget/{id}/chat | untrusted public input (the question) crosses into the agent turn |
| Celery runtime worker → Voyage API | per-turn query embedding leaves the VM (only the question text, no secrets) |
| Celery runtime worker → Upstash Redis (qembed cache) | cached query vectors stored remotely over rediss:// TLS |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-12-01-01 | Denial of Service | retrieve loop exhausting Voyage 3 RPM (the actual 2026-05-29 live failure: 6 retrieves/turn) | mitigate | D-10 dual guard: `max_turns=3` in ClaudeAgentOptions + system-prompt "retrieve at most once" instruction — caps Voyage calls to 1-2 per turn |
| T-12-01-02 | Denial of Service | turn killed prematurely by too-tight wall-clock guard on slower ARM SDK warm-up | mitigate | D-11: raise `asyncio.wait_for` timeout to 90s; SSE layer retains 120s (30s headroom) so it never races the task guard |
| T-12-01-03 | Information Disclosure | query-embedding cache leaking sensitive data | accept | Cached value is only the question's embedding vector (non-reversible, non-PII beyond the question text key-hash); stored over rediss:// TLS on existing Upstash; 1h TTL. No new secret surface. |
| T-12-01-04 | Tampering | a poisoned cache entry returning a wrong vector | accept | sha256 key derived purely from the query string; only this app writes the key; corpus already embedded and immutable; impact is at worst a stale-but-valid vector within 1h TTL. Low value target. |
</threat_model>
