Wave 2 builds the first task of the M2 ingestion chain: `parse_documents`. It owns:
1. A thin service wrapper (`docling_service.py`) holding the module-level `DocumentConverter` instance and two pure functions for parsing files vs URL-fetched bytes.
2. The Celery task itself — fetches the tenant DB connection from the control DB by agent_id, applies the document-level source_hash idempotency guard (Layer 1 of 4), parses each document, writes parse_status='parsed' (and source_hash if previously NULL), emits `ingestion.started`, `parsing.started`, `parsing.complete` to the job's SSE stream.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Celery broker → worker | Task arguments cross Redis; mitigated by NEVER placing connection strings or API keys in args |
| local filesystem → DocumentConverter | Uploaded PDF reaches Docling parser; malicious PDFs could exploit ML model parsing — mitigated by Docling parsing in worker process isolation |
| URL → httpx → DocumentConverter | URL-fetched bytes cross the trust boundary; mitigated by httpx timeout + Docling parser sandboxing |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-02-01 | Information Disclosure | parse_documents task args | mitigate | Task signature is `(self, tenant_id, agent_id, job_id, document_ids)` only; connection string fetched at runtime via `fernet_decrypt(agent.neon_connection_string)`; verified by test `test_parse_documents_no_conn_string_in_signature` (CLAUDE.md non-negotiable) |
| T-02-02-02 | Tampering | malicious PDF parsing | mitigate | Docling runs in the same worker process — risk accepted as Docling is a trusted IBM library; future hardening (separate parser subprocess) deferred. RuntimeError from ConversionStatus != SUCCESS is caught and marked parse_status='failed' so a single bad PDF does not break the chain |
| T-02-02-03 | Denial of Service | URL fetch | mitigate | httpx.get uses timeout=30 seconds explicit; follow_redirects=True only (no infinite redirect by default); response.content size bounded at the route layer by MAX_UPLOAD_SIZE_MB enforcement (Wave 6) |
| T-02-02-04 | Information Disclosure | structlog calls | mitigate | log.* calls reference document_id, page_count, and error type/message ONLY — never the source content or fetched URL body. Connection string `tenant_conn_str` is held in a local variable, never logged |
| T-02-02-05 | Repudiation | task retries | mitigate | acks_late=True ensures task message stays in queue until success or final failure; 4-layer idempotency guarantees retries are safe (Layer 1 = source_hash guard implemented in this task) |
| T-02-02-06 | Tampering | re-ingest with new bytes | mitigate | source_hash mismatch triggers full re-parse; old chunks remain orphaned but a new document_id can be issued by the route on re-upload (route logic — Wave 6). For same document_id with same hash, parse is a no-op |
</threat_model>
