<objective>
Wave 3 builds the second pipeline task: `chunk_documents`. It re-parses each parsed document through the two-path chunking strategy (text via HybridChunker, tables via Markdown export) and writes deterministic chunk rows to the tenant DB.

Three core responsibilities:
1. `chunking_service.chunk_document(doc, document_id) -> list[dict]` — pure function that produces ordered chunk dicts. Tables NEVER go through HybridChunker (PITFALLS.md §2). Each chunk text passes through `sanitize_chunk_text()` to strip injection markers.
2. `chunk_documents` Celery task — re-parses each document via Docling (Docling output is not serialised between tasks; cheaper to re-parse than to round-trip a 100MB+ object), splits into chunks via the service, and UPSERTs each chunk into the tenant `chunks` table.
3. Layer 2 idempotency — deterministic uuid5 chunk IDs combined with ON CONFLICT DO UPDATE means re-running the chain overwrites with identical content, never duplicates.

Purpose: This is the first task in the chain that writes user-derived content to the tenant DB. Sanitization fires here, so M7's red team probe of the corpus will find clean chunks.
Output: Each parsed document yields N rows in the tenant `chunks` table with stable IDs and updated `documents.chunk_count`.
</objective>

    Function signature: `def chunk_document(doc, document_id: str) -> list[dict]:`

    Returns ordered list of chunk dicts; each dict has these keys (NO others — schema must match Wave 5 INSERT statement):
    - "id": str (UUID string from deterministic_chunk_id)
    - "text": str (sanitized; ready to write into chunks.content)
    - "ordinal": int (zero-indexed, monotonic across both paths)
    - "is_table": bool (True for the table path, False for HybridChunker output)
    - "token_count": int (approximation: len(text.split()) — replace with proper tokenizer in M3 if needed)

    Implementation order — text path FIRST, then table path appended:

    1. Initialise: chunker = HybridChunker(max_tokens=512, merge_peers=True); chunks = []; ordinal = 0.

    2. Text path:
       for chunk in chunker.chunk(doc):
           # Skip chunks that contain ANY TableItem instance — those are handled separately
           has_table = any(isinstance(item, TableItem) for item in getattr(chunk.meta, "doc_items", []))
           if has_table:
               continue
           text = sanitize_chunk_text(chunker.contextualize(chunk))  # contextualize prepends heading breadcrumb; sanitize strips injection markers
           if not text:
               continue
           chunk_id = deterministic_chunk_id(document_id, ordinal)
           chunks.append({
               "id": str(chunk_id),
               "text": text,
               "ordinal": ordinal,
               "is_table": False,
               "token_count": len(text.split()),
           })
           ordinal += 1

    3. Table path:
       for table in doc.tables:
           md = table.export_to_markdown(doc=doc)  # IMPORTANT: pass doc=doc for proper formatting
           if not md.strip():
               continue
           text = sanitize_chunk_text(md)
           if not text:
               continue
           chunk_id = deterministic_chunk_id(document_id, ordinal)
           chunks.append({
               "id": str(chunk_id),
               "text": text,
               "ordinal": ordinal,
               "is_table": True,
               "token_count": len(text.split()),
           })
           ordinal += 1

    4. log.info("chunking_service.complete", document_id=document_id, chunk_count=len(chunks), table_count=sum(1 for c in chunks if c["is_table"]))

    5. return chunks

    def chunk_documents(self, result: dict) -> dict:

    Body:
    1. Extract from result: tenant_id, agent_id, job_id, document_ids. Validate keys present; if not, log error and return result unchanged (defensive — chain may have been re-dispatched mid-flight).

    2. Open `with get_sync_db() as db:`. Fetch agent. Decrypt POOLED conn string. Open `tenant_conn = psycopg2.connect(conn_str)`; wrap remainder in try/finally tenant_conn.close().

    3. For each doc_id in document_ids:
       a. Query tenant: `SELECT source_uri, source_type, parse_status, chunk_count FROM documents WHERE id = %s`. If row missing or parse_status != 'parsed', log warning and continue (defer until parse succeeds).
       b. Idempotency observation (Layer 2 is in the upsert itself, but we can log skip if chunk_count is already set AND > 0 — though we still re-write for safety; do NOT skip the work because the deterministic IDs make rewrites cheap and consistent).
       c. emit(job_id, "chunking.started", {"document_id": doc_id, "document_count": len(document_ids)}, db, _redis)

       e. chunks = chunk_document(doc, doc_id).
       f. With tenant_conn.cursor() as cur:
          For each chunk in chunks:
            cur.execute(
              """
              INSERT INTO chunks (id, document_id, ordinal, content, token_count)
              VALUES (%s, %s, %s, %s, %s)
              ON CONFLICT (id) DO UPDATE
                  SET content     = EXCLUDED.content,
                      token_count = EXCLUDED.token_count,
                      ordinal     = EXCLUDED.ordinal
              """,
              (chunk["id"], doc_id, chunk["ordinal"], chunk["text"], chunk["token_count"]),
            )
          cur.execute("UPDATE documents SET chunk_count = %s WHERE id = %s", (len(chunks), doc_id))
          tenant_conn.commit()
       g. emit(job_id, "chunking.complete", {"document_id": doc_id, "chunk_count": len(chunks)}, db, _redis)
       h. log.info("chunk_documents.complete", document_id=doc_id, chunk_count=len(chunks))

    4. On exception: tenant_conn.rollback() (best-effort); log error; raise self.retry(exc=exc, countdown=2**self.request.retries) for transient errors.

    5. Return identical dict shape: {"tenant_id": tenant_id, "agent_id": agent_id, "job_id": job_id, "document_ids": document_ids}.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Docling output → tenant DB | Chunk text derived from user-uploaded documents; mitigated by sanitize_chunk_text before INSERT |
| Celery broker → worker | Task receives only the result dict from parse_documents; no secrets cross the broker |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-03-01 | Tampering | chunk text content | mitigate | Every chunk text — both HybridChunker output (via chunker.contextualize) and table Markdown — passes through sanitize_chunk_text() before INSERT. Strips System:/Human:/Assistant:/injection tag patterns/HTML comments/"Ignore previous" patterns (PITFALLS.md §11) |
| T-02-03-02 | Information Disclosure | structlog calls | mitigate | log calls reference document_id, chunk_count, table_count ONLY — never chunk content. Connection string held in local variable, never logged |
| T-02-03-03 | Repudiation / DoS on retry | chunks table | mitigate | Layer 2 idempotency: deterministic uuid5 chunk IDs + INSERT ... ON CONFLICT (id) DO UPDATE. Worker kill mid-loop is safe; subsequent retry overwrites with identical content. No chunk-row leak per retry |
| T-02-03-04 | Information Disclosure | task args | mitigate | Task signature is `(self, result: dict)`; result contains tenant_id, agent_id, job_id, document_ids — verified by test_chunk_documents_signature_takes_only_result_dict. Connection string fetched at runtime |
| T-02-03-05 | Tampering | re-parse mid-chain | accept | Re-parsing the same file via Docling between parse_documents and chunk_documents is non-deterministic only at the millisecond level (page rendering); chunk content is determined by HybridChunker which is deterministic given the same DoclingDocument input. Variation accepted as cheaper than serialising 100MB+ DoclingDocument through Redis |
| T-02-03-06 | DoS | URL re-fetch | mitigate | URL re-fetch in chunk_documents reuses httpx timeout=30; same mitigation as parse_documents |
</threat_model>
