# Phase 4.2 Plan 02: Backend Prerequisites for Widget Config Summary

**One-liner:** Alembic migration 0009 adds `widget_config` JSONB to agents, backed by three new FastAPI routes and hex-validating Pydantic schemas for the admin widget customization panel.

## What Was Built

Three backend prerequisites needed by every Phase 4.2 frontend page:

1. **Alembic migration 0009** (`0009_agent_widget_config.py`) — `ALTER TABLE agents ADD COLUMN widget_config JSONB NOT NULL DEFAULT '{}'::jsonb`. Chains from 0008 (tenant daily budget).

2. **Agent ORM field** — `widget_config: Mapped[dict]` with `JSONB` type and `server_default=text("'{}'::jsonb")` added to `app/models/agent.py`.

3. **Four Pydantic schemas** appended to `app/schemas/agent.py`:
   - `AgentListResponse` — wraps `list[AgentResponse]` for the dashboard list endpoint
   - `WidgetColorsSchema` — 9 hex-validated color fields (T-04.2-02-03 threat mitigation)
   - `WidgetTypographySchema` — font + border radius with `Literal` constraints
   - `WidgetConfigUpdate` — top-level widget config request body with `Field(default_factory=...)` for nested defaults

4. **Three FastAPI routes** added to `app/api/v1/agents.py`:
   - `GET /agents` — lists all non-deleted agents for the tenant, ordered by `created_at DESC`
   - `GET /agents/{id}/widget-config` — returns stored JSONB config; 404 on IDOR
   - `POST /agents/{id}/widget-config` — validates and persists `WidgetConfigUpdate`; 404 on IDOR

5. **7 unit tests** in `tests/unit/test_agents_list_and_widget_config.py` — all pass:
   - `test_list_agents_returns_tenant_scoped_list`
   - `test_list_agents_filters_by_tenant_id`
   - `test_get_widget_config_returns_stored_jsonb`
   - `test_get_widget_config_returns_empty_dict_when_unset`
   - `test_save_widget_config_persists_payload`
   - `test_save_widget_config_rejects_invalid_hex`
   - `test_widget_config_not_owned_returns_404`

## Deviations from Plan

### Pre-existing Test Failure (Out of Scope)

`test_agents_patch.py::TestPatchAgent::test_patch_agent_strips_empty_list_items` fails with 422 instead of 200. Confirmed pre-existing by stashing this plan's changes and re-running — test still fails. Root cause: `AgentSoulUpdate.soul_do_list` items have `Annotated[str, Field(min_length=1)]` constraint, so Pydantic rejects `""` with 422 before the route body's strip logic can run. This is a design conflict in the existing schema, predating Phase 4.2. Logged to `.planning/phases/04.2-landing-homepage/deferred-items.md`.

No other deviations. Plan executed exactly as written.
