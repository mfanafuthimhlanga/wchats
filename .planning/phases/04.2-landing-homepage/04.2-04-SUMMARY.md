## What Was Built

### Task 1: JourneyStepper + StepSubtaskCard

**JourneyStepper** (`apps/admin/app/components/JourneyStepper.tsx`):
- 320px fixed-width `<aside>` with `var(--bg)` background and `var(--border-soft)` right border
- Agent name header (18px bold) + role subtitle (13px `var(--text-3)`)
- 4-step vertical layout with done/active/locked states:
  - Done: wine fill circle (`var(--accent)`) + checkmark + green "Done" chip
  - Active: white circle with wine border + step number + `var(--accent-dim)` container background
  - Locked: `var(--surface-3)` circle + 60% opacity container
- Vertical connector line between steps (wine at 0.35 opacity for done steps, `var(--border-soft)` otherwise)
- Optional `href` prop wraps row in `<Link>` when step is not locked
- Exports: `default JourneyStepper`, `type StepState`, `interface JourneyStep`, `interface JourneyStepperProps`
- No `className=` usage — inline styles exclusively

**StepSubtaskCard** (`apps/admin/app/components/StepSubtaskCard.tsx`):
- 40px icon block with `var(--accent-dim)` background
- Title (14px bold) + description (12px `var(--text-3)`)
- State-aware left border: 3px `var(--green)` for completed, 3px `var(--accent)` for active, 1px `var(--border-soft)` for idle
- CTA: `<Link>` (with href) or `<button>` (with onCtaClick) — primary style when state=active
- No `className=` usage

### Task 2: Agent Journey Page + Stubs

**`/agents/[id]`** (`apps/admin/app/agents/[id]/page.tsx`):
- Client component with `use(params)` to unwrap id
- Fetches `GET /api/v1/agents/{id}` with Bearer JWT via `useAuth().getToken()`
- `deriveStepState()` derives step states from `agent.status` and `neon_project_id`
  - Step 1 (Provision): done if status=ready/provisioning_complete OR neon_project_id set
  - Step 2 (Configure): active once step 1 done; locked otherwise
  - Step 3 (Test): active once step 2 done; locked otherwise
  - Step 4 (Deploy): locked until step 3 done
- 2-column layout: `<JourneyStepper>` left + `<section>` right with 4 `<StepSubtaskCard>` items
- Cards link to: `/agents/${id}/soul`, `/agents/${id}/ingest`, `/agents/${id}/eval`, `/agents/${id}/deploy`
- Error alert pattern from soul/page.tsx

**`/agents/[id]/ingest`** (stub):
- `use(params)` unwrap, `← Back to Configure` link, "Coming soon" placeholder card

**`/agents/[id]/eval`** (stub):
- Same pattern, text changed for Ragas metric dashboard

### Task 3: Create-Agent Wizard

**`/agents/new`** (`apps/admin/app/agents/new/page.tsx`):
- Three-phase state machine: `form` | `provisioning` | `error`
- Form: name text input + role select (support/sales/helpdesk) + submit button
- On submit: validates name, calls `POST /api/v1/agents` with Bearer JWT + `{ name, role, soul: {voice:'', do:[], do_not:[]} }`
- On 2xx: starts `setInterval(pollFn, 2000)` polling `GET /api/v1/agents/{id}`
  - On `status='ready'`: `clearInterval` + `router.push('/agents/{id}')`
  - On `status='error'`: `clearInterval` + show error phase
- On non-2xx: shows error phase
- `useEffect` cleanup clears interval on component unmount
- `handleReset` clears interval and returns to form phase
- Zero `EventSource` references
